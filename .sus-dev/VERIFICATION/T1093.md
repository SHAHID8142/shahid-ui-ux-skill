# T1093 — issue #25: closed-session retention must not exceed the configured session cap

Date: 2026-11-20 · Agent: `sus-release` (darwin/SSD) · Branch: `release/v0.1.0-preview.1-prep`
Fix commit: `a91424e` (same commit as T1092 — one coherent bridge-hardening change)

## Finding (Codex preliminary recheck)

Codex's in-memory probe on `c45c789`: 20 open→close cycles left 20 retained entries despite
`maxSessions=16`. Source inspection: `closeSession()` only set `status='closed'`;
`pruneExpired()` removed only expired **active** sessions; `openSession()`'s cap eviction searched
only **active** entries, so a map full of closed entries had no evictable target and grew anyway.
The probe did NOT show closed tokens staying authorized — `verifyToken` already rejected them —
and this fix keeps that property.

## Fix

- **`closeSession()` deletes the entry** and records a `session-closed` audit event (event added
  to the `AuditEntry` union). A closed entry was dead weight — `verifyToken` rejects it — so the
  closed state now lives in the audit trail, not in the map. Fail-closed semantics unchanged.
- **The cap bounds TOTAL retained entries:** `openSession()` keeps active-LRU eviction first
  (leaked-token protection), and gains an any-status fallback eviction so a future path that
  leaves a non-active entry behind cannot grow the map past `maxSessions`. With deletion on
  close, the fallback is defence in depth and should never fire.

## Tests (same commit; `server.test.ts` 16 → 31 tests)

- **100 open/close cycles** at a cap of 16: `sessions.size ≤ 16` asserted before and after every
  close; every closed session absent from the map; every token dead; 100 `session-closed` audits.
- **The exact Codex probe**: 20 open/close cycles at the default cap → at most 16 retained,
  20 `session-closed` events.
- Closing does not revive: old id/token rejected; a reopened session gets a fresh id and works.
- Cap-1 slot reuse: the stale token stays dead after the slot is reused.
- Existing T1062 tests still pass unchanged: absolute-deadline pruning, idle expiry + renewal,
  active-LRU eviction at the cap, evicted token rejection, post-restart ignorance.
