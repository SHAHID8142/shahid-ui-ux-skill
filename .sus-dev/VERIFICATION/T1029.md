## Why classification is tested rather than trusted

The failure this guards is a human one: a PR titled "Independent review" that also contains
`TASKS.json`, `ROADMAP.md`, `HANDOFF.md` and `docs/OWNER_DECISIONS_LOG.md` edits. Merging it would not
import a review, it would revert the canonical record to the `main` planning baseline while keeping the
code. The classifier keys on files, not titles, and a test asserts that a PR mislabelled as harmless
still lands in `state-overwriting`.

## Deliberately not done

- **No ruleset applied.** It is an admin setting with irreversible effects on the owner's workflow; the
  proposal, the exact read-back commands and a safe negative test are in `docs/GOVERNANCE.md` §1.
- **No PR closed or branch deleted.** Recommended, recorded, left to the owner/maintenance policy.
- **No LICENSE added and no `license:` field changed.** `SKILL.md` says proprietary; adding a permissive
  licence without a decision would be a false legal statement.
- **No package or release published.** T1005 stays owner-only; T1003 remains `pending` and is not
  self-certified anywhere in this receipt.
- The inventory is a snapshot: re-running `pnpm review:index` after new PRs fails until the snapshot is
  refreshed, which is the intended prompt, not an error.
