# T1036 — the motion dimension is measured by driving one disclosure (issue #21 R7)

**Task:** issue #21 R7: `transition-oracle` needed an interaction and no run drove one, so the motion
dimension was `not-run` for every target forever and the reduced-motion guard shipped unmeasured.
**Approval:** D32 issue triage inside D28; the owner's `go ahead` on the R-series.
**Branch / base:** `chore/continuation-reconciliation` at `e790366`.

## Verdict

**Pass on the narrow claim it makes**, and the narrowness is stated: motion is measured for a page that
contains a disclosure (an element declaring `aria-expanded`), by driving it in pointer, keyboard and
`prefers-reduced-motion: reduce` contexts. A page with no such element reports `not-run` with that
reason. G6 therefore means "this disclosure kept its information under reduced motion", not "all motion
is verified".

## What was actually blocking

`transition-oracle.ts` evaluates **recorded traces** on purpose (an oracle built from the generator that
produced the transitions would only agree with itself). Nothing produced a trace, so the check was
hard-coded `not-run`. The missing piece was small: drive something, record what a user sees, hand it to
the oracles.

## Design decisions

| Decision | Reason |
| --- | --- |
| Drive a disclosure (`aria-expanded`), not a guessed click target | It is self-describing and the state change is machine-readable; clicking "some button" would be inventing a scenario |
| Three contexts: pointer, keyboard, reduced motion | Parity is a comparison; a single trace cannot show that reduced motion lost information |
| Compare **information tokens**, not CSS | Kilo M2: the user must keep the state and the readable text; a shorter duration is the goal, not a defect |
| Visibility read explicitly (`checkVisibility`) | `innerText` on a hidden element falls back to `textContent`, which made the lossy fixture look identical to the honest one — the test caught this |
| Own browser contexts | `prefers-reduced-motion` is context-level emulation, so it cannot share the axe page |
| Route, not URL, in reports | The bound local port is ephemeral; a finding must not cite `http://127.0.0.1:49607/` |

## Measured

| Fixture | G6 | Detail |
| --- | --- | --- |
| `fixtures/bestpractice/motion` (guards the animation, keeps the panel) | **pass** | `button#toggle: 2 transition trace(s) pass every oracle`, transition 180 ms |
| `fixtures/bestpractice/motion-lost` (hides the panel under reduced motion) | **fail** + P1 finding | `reduced-motion-information-lost — missing "Invoice 2026-10-31: 1,440…"`, located at `button#toggle`, `observed 1 / expected 0` |
| `fixtures/bestpractice/scoped-axe` (no disclosure) | **not-run** | `no element declares aria-expanded, so there is no disclosure to drive` |

Through the real command, the motion dimension now reaches a scoped proposal:

```
sus bestpractice --path fixtures/bestpractice/motion-lost --scope page --mode deep
→ 3 item(s), 3 measured, 1 blocking
  P1 | fact | motion | Motion parity: reduced-motion: red... | `button#toggle`
```

Before this, a `motion` item could not exist: the dimension was permanently untested, so no finding was
ever mapped to it.

## Proof

`packages/eval-core/tests/motion-probe.test.ts` — 4 tests, green: honest fixture passes, lossy fixture
fails with the named rule, a page with nothing to drive is `not-run` with a reason and **no verdict**,
and `motionCases` builds the reduced-motion + keyboard cases whose traces carry the same information.

## Second issue found: a timeout that measured the runner, not the code

The deep best-practice test timed out on CI at exactly 180 s while taking ~111 s locally. Measured, not
assumed: the same audit takes 106 s with the motion probe and 109 s without it, so the probe was not the
cause — a five-route deep audit (capture, reflow, axe, keyboard, Lighthouse, motion, plus a full
Lighthouse budget run per route) simply exceeded the budget on a loaded runner. The test keeps its
assertions and gets 420 s of headroom, with the measurement recorded in the test comment.

## Stated limits

- Hover-only transitions, carousels, drag gestures and scroll-linked animation are **not** driven.
- The claim is parity of information on the driven disclosure; a page can still have unmeasured motion.
- `quick` mode has no browser phase, so motion stays `not-run` there, unchanged.
- The probe drives the first `[aria-expanded]` element only; a page with several disclosures is measured
  on one, and the check says which (`button#toggle`).
