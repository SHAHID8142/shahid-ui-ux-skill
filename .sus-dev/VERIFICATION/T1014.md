# T1014 — Seven gates stop being `not-run`: G2, G3, G6, G7, G8, G9, G10 execute in the build

**Status:** done · **Milestone:** M10 · **Date:** 2026-11-16 · **Owner:** lead (root agent)

## Why

The registry said `not-run` for seven gates. The harness fields existed, the evaluators existed in
some cases, and `scripts/check-gates.mjs` ran none of them — so the honest reading of the build was
"eleven gates are checked, seven are described." A registry entry that names a check nobody runs is
the exact failure T0159 exists to prevent, one level up: it looks like coverage and is a sentence.

Two things had to be true at once. Each gate needed an executable check with a **negative** — a bad
fixture that makes it fail — because a check that has only ever seen good input has not been shown
to reject anything. And the human-readable table had to stop being able to say `implemented` while
the JSON said `not-run`, or the documentation would keep describing an intention.

## What was added

### Seven plain-JavaScript evaluators (`scripts/lib/gates/`)

`check-gates.mjs` must run on a tree that has never been built — it is the gate checker, so it
cannot depend on `dist`. Each gate therefore lives in a small `.mjs` module with no build step:

| Gate | Module | What it decides |
| --- | --- | --- |
| G2 | `g2-section-order.mjs` | a section may not be `accepted` while its predecessor is not — a map-based walk over `order`, mirroring `sectionLockViolation` in `packages/schemas/src/progressive.ts` |
| G3 | `g3-placeholder-claims.mjs` | filler text, authoring markers (TODO/FIXME/TBD/"coming soon"), and numeric claims not present in the claims register |
| G6 | `g6-motion-parity.mjs` | information-token parity between default and reduced-motion traces, checked in both directions |
| G7 | `g7-reflow.mjs` | 320 CSS px overflow, **and** `overflow: hidden` masquerading as reflow; the 400 % zoom half is reported `not-run` out loud |
| G8 | `g8-target-size.mjs` | the 24×24 CSS px floor with only the four SC 2.5.8 exceptions (inline, equivalent, user-agent, essential) |
| G9 | `g9-semantics.mjs` | heading ladder, `main` landmark, click-only controls, removed focus indicator |
| G10 | `g10-detector-precision.mjs` | precision/recall against the registry's own numeric targets, over the labelled corpus |

Each module's header states the failure it prevents and the fail-closed rule it follows. G2's says
the mirror is deliberate: the fixtures are what keep the plain-JS copy and the TypeScript copy from
drifting apart silently.

### Wiring and fixtures

`scripts/check-gates.mjs` now runs, for each of the seven: the good fixture (must pass) and the bad
fixture (must fail), plus a fail-closed probe where a gate can be starved of input — no traces for
G6, no 320 px record for G7, no controls for G8, no labelled cases for G10. Those probes are the
reason `not-run` cannot be quietly upgraded to `pass`.

Fourteen JSON fixtures under `scripts/gates/fixtures/` (`g{2,3,6,7,8,9,10}-{good,bad}.json`), each
bad one producing a *specific*, human-readable violation rather than a generic rejection.

### Registry reconciliation

`docs/GATE_REGISTRY.json` moved all seven to `checkStatus: implemented` with a `check` string naming
the module and a `badFixture` path. `docs/GATE_REGISTRY.md` was rewritten in the same change, so the
table and the JSON say the same thing — a checker asserts that agreement rather than trusting a
reviewer to notice.

## Guards

- **Every gate has a negative.** A gate whose check has only seen good input is unverified.
- **Fail-closed probes.** Empty input is `not-run` or `fail`, never `pass`: `G7: no 320px measurement
  is not-run, never pass`, `G8: no measured controls is not-run, never pass`, `G10: no labelled cases
  fails closed`, `G6: no recorded traces fail closed`.
- **Mutation sweep.** Substituting each bad fixture into its good slot must make the checker exit
  non-zero with *that* gate's `[FAIL]` line — seven for seven, measured below.
- **The G10 corpus cannot go stale.** A check compares the fixture's predictions against the shipped
  detector, so a detector change that the corpus did not follow is caught.
- **G7 has no 400 % alibi.** Line 16 of the output states the zoom component is `not-run` because
  the harness does not drive browser zoom, and that the 320 px measurement does not stand in for it.
- **The registry cannot self-certify.** `node scripts/check-gates.mjs` exits 1 if any
  `checkStatus: implemented` gate lacks a `check` or a `badFixture`.

The sweep numbers are the point: seven substitutions, seven catches, and no false pass anywhere in
the set. A gate that cannot be made to fail on its own bad fixture is not measuring anything.

## Not claimed

- **G7's 400 % zoom component is still `not-run`.** A headless page can be sized; browser zoom is a
  user-agent setting this project never drives. That half stays unmeasured and is announced on
  every run — this change narrowed the gap, it did not close it.
- **G6 over the fixtures.** Motion parity is decided over recorded traces; a target that authored no
  traces is `not-run`, and the audit repeats that the transition oracle is unverified rather than
  passed.
- **G3 is a scanner, not a writer.** It detects filler and unregistered numeric claims; it cannot
  judge whether the copy a human wrote is any good.
- **No gate was relaxed.** Every `checkStatus` moved in one direction only (`not-run` →
  `implemented`); no owner task list, threshold or waivability changed. G13 remains never waivable.
