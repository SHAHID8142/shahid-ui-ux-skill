# T1013 — Evidence per finding, an ordered report, and tests that try to break both

**Status:** done · **Milestone:** M10 · **Date:** 2026-11-16 · **Owner:** lead (root agent)

## Why

Issue #13 sections 4–6 ask for something more specific than a findings list: each finding has to
carry the machine-readable record behind it, the report has to separate what a machine measured
from what only a person can judge, and the whole thing has to survive tests written to make it lie.

The failure this prevents is the quiet one. A finding with a blank `observed` field, an artefact
path with no hash, or a "pass" stamped on a screen-reader question looks like evidence and is none.
So every one of those shapes has to be *unrepresentable*, not merely discouraged.

## What was added

### The observation record (`report.ts`)

Every finding carries a strict `observation` object. All nine keys are required, so a consumer can
tell "deliberately reported as unknown" (`null`) from "nobody recorded it" (a shape that cannot be
produced):

`evaluator`, `expected`, `observed`, `location`, `artifact`, `artifactHash`, `confidence`,
`verdict`, `remediation`.

`superRefine` makes four combinations unrepresentable:

1. an artefact path with no `sha256` — an unhashed artefact cannot be checked later;
2. a `sha256` with no artefact path — a hash that points at nothing;
3. `confidence: 'measured'` against a non-null `expected` but a `null` `observed` — an instrument
   reading has to say what it read;
4. `confidence: 'unjudged'` with `verdict: 'confirmed'` — a machine cannot confirm a human judgment.

`confidence` is the load-bearing field: `measured` (instrument reading), `inferred` (pattern
heuristic — the anti-slop rules are exactly this), `unjudged` (human-only). Environment and run
provenance stay at report level on purpose: one run has one environment, and a per-finding copy
could disagree with itself.

### The report (`report.ts`, `compose.ts`)

`AuditSummary` counts P0–P3 plus `quickWins`, `structural`, `needsReview` and `incomplete`, and
`superRefine` cross-checks the counts against the findings list so a hand-edited summary fails.
`sortFindings` orders worst-first with a stable tiebreak; `stableFindingId` hashes check + route +
viewport + title. `exitCodeFor` folds severities into 0/1/3. `renderAuditMarkdown` emits the
executive summary, the severity table, the findings with their citations, and the needs-review list.

`compose.ts` attaches artefacts by exact `route|viewport` match and falls back to `route|*` for
findings that name no viewport. A finding whose viewport was never photographed (the 320 px column
is metric-only) keeps `artifact: null`. Substituting a nearby shot would be the one thing worse
than no evidence.

### Tests (`packages/eval-core/tests/audit.test.ts`, 39 total)

The `audit evidence contract (T1013)` block is eleven tests, deliberately adversarial:

- refuses a finding with no observation at all;
- refuses an artefact with no hash, and a hash with no artefact;
- refuses a machine verdict on a human-only item;
- points a finding at the artefact that records it, hash included;
- cites the shot of the screen the finding was measured on;
- falls back to the route shot when a finding names no viewport;
- **leaves the artefact empty rather than inventing one**;
- **does not let hostile page content fabricate a verdict**;
- degrades to `not-run`, not to a pass, when the host is unavailable;
- degrades every browser phase to `not-run` when no browser is available;
- passes G11 only when a complete bundle exists, and stays `not-run` otherwise.

Plus the fix-plan gate: `runAudit(..., { fixPlan: true })` writes `fix-plan.json` whose every
proposal says `requiresApproval: true, applied: false`, and the target is unchanged afterwards.

## Guards

- **Hashing lives in one place.** `sha256OfFile` in `pipeline.ts` is the only hashing the audit
  performs; `compose.ts` stays pure and never touches the filesystem.
- **Adversarial content.** A fixture page whose own text contains audit-shaped strings cannot
  produce a finding: findings are composed from evaluator output, never from page content.
- **Fail-closed bundles.** `evaluateG11` needs ≥1 shot, ≥1 metrics sample and ≥1 G4/G5 verdict;
  otherwise the bundle is not emitted and the check is `not-run`.
- **Summary honesty.** `incomplete: true` whenever a required check is `not-run`, and a `not-run`
  check without a reason is a validation error.

## Not claimed

- `needsReview` lists seven items the harness cannot decide: blind human A/B rating, a real
  screen-reader session, browser zoom at 200 %/400 %, real translations and RTL, content volume
  beyond the fixtures, host support beyond `docs/SUPPORT_MATRIX.md`, and unauthored transition
  oracles. They are listed on every run; none of them is ever auto-passed.
- The evidence bundle is built from what this run produced. It is not a substitute for the
  release-time bundle a real project assembles from its own gated runs.
- `--fix-plan` proposes text; it never edits the target, and re-running the audit is required
  after any human applies a change.
