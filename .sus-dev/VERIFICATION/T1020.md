# T1020 — one thing issue #13 refused to close without: a scroll container is not overflow

**Task:** issue #13's acceptance says negative fixtures must catch failures "without hiding data
or creating false positives for legitimate scrollable grids". Measured against that clause, the 400%
zoom record failed it: `measureZoom400` treated **any** leaf wider than the viewport as overflow, so
a data grid inside `overflow-x: auto` — a pattern SUS's own `MOBILE_RECORD_PATTERNS.md` recommends —
would have been reported as a defect at 320×256.
**Approval:** D32 issue triage (issue #13, P1) within D28 build authorization.
**Branch / base:** `chore/continuation-reconciliation` at `2c44d8e`.

## The defect, precisely

```ts
// before: packages/eval-core/src/harness/metrics.ts
if (rect.width > 0 && rect.right > vw + 1 && el.children.length === 0) overflowing.push(...)
```

`overflowingElements` is consumed by the zoom record, which ORs it into `overflow`. So a wide leaf
inside a reachable, cued scroll region counted the same as a leaf with nowhere to go. The matrix
cell was already correct (it reads `documentElement.scrollWidth > clientWidth`); the zoom half was
not, and the audit's `reflow-matrix` finding cites it.

## The rule now

| Ancestor state | Counted as overflow? | Why |
| --- | --- | --- |
| no clipping/scrolling ancestor | **yes** | the page needs two-dimensional scrolling |
| ancestor `overflow-x: auto` or `scroll` | **no** | the content is reachable and the container is cued; this is containment |
| ancestor `overflow-x: hidden` or `clip` | **yes** | the content is unreachable and the page merely stopped scrolling — hiding is not a fix |

That last line is deliberate: the cheap way to make an overflow check pass is to clip the overflow,
and the audit must not reward it. `docs/MOBILE_RECORD_PATTERNS.md` already forbids
`overflow-x: hidden` on the page for exactly this reason, so the code and the guidance now agree.

## Measured (three cases, real browser)

| Fixture | Matrix cell | Zoom record |
| --- | --- | --- |
| 900 px block inside `overflow-x: auto` | no document scroll, no leaf reported, `overflow: false` | `overflowingElements: []`, `overflow: false` |
| 900 px block, no scroller | `overflow: true` in at least one cell | `overflow: true`, one leaf named |
| 900 px block inside `overflow-x: hidden` | no document scroll (clipped), `overflow: false` | `overflow: true`, one leaf named |

The third row is the interesting one: the page looks clean to a document-level check *because the
content is being destroyed*, and only the leaf list catches it.

## What this does not claim

- **A scroll container is not automatically *good*.** This changes whether the leaf is scored as
  page overflow, not whether the grid is usable: arrow-key scrollability, a visible affordance and a
  frozen first column are separate checks (`MOBILE_RECORD_PATTERNS.md`, `keyboard-flow`).
- **Nested cases are simplified:** the first `auto|scroll` ancestor decides. A scroller inside a
  clipping ancestor is treated as containment, which is what a user experiences.
- **`overflow: overlay`** is not special-cased; it is treated as neither, so the leaf is named.
