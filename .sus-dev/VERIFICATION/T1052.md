# T1052 — the report says what the network boundary refused (audit finding T1003-7)

Date: 2026-11-18 · Agent: zcode-audit · Branch chore/continuation-reconciliation

## What changed

- **Schema** (`packages/eval-core/src/audit/report.ts`): `AuditReport` gains
  `networkRefusals: string[]` (`.default([])` so hand-built reports and older tools parse; absent
  and empty mean the same thing — nothing was refused, never a silent omission of a half-loaded
  page).
- **Composer** (`packages/eval-core/src/audit/compose.ts`): `AuditInputs.networkRefusals?` threads
  the refusal list into the report; the composer deduplicates.
- **Renderer** (`renderAuditMarkdown`): when refusals exist the report carries a
  "## Network boundary" section — the refused requests, the statement that their content is **not
  in these measurements**, and the stated subresource allowance (the tool constrains which hosts
  it contacts, not which bytes an authorised page pulls). Nothing refused → no section, `[]` in
  JSON. The header promise in net-guard ("a stated limitation, printed in the report's limitations
  rather than hidden") is now implemented instead of asserted.
- **Pipeline** (`collectScans`): gathers `proxy.refused()` from the guarded browser's proxy, the
  navigation guards' `blocked()` lists (axe page + keyboard page) and the Lighthouse phase's own
  proxy (T1046), before each is closed; `runAudit` carries the list into the inputs. Quick mode
  (no browser phases) reports `[]` by construction.
- **docs/LIMITATIONS.md** §4: the boundary's what-is/is-not-constrained statement, as the
  net-guard header always claimed it would be.
