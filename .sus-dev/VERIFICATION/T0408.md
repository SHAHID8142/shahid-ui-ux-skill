## What the acceptance actually demanded

"Imagery plan required" is only meaningful if its absence is an error, so the plan
is a **required field of the direction record**, not a separate document — the
rollback note ("licensing field mandatory") says the licence is the load-bearing
part. Both are now schema-level: a record without `imagery` fails
`schema:imagery`, and an asset whose `permitsCommercial` is not the literal `true`
cannot be described at all.

## The three failures this is shaped around

1. **The hero with no known licence.** Per asset: `name`, `proofRef` (a licence
   nobody can produce is a rumour), `attributionText` when `requiresAttribution`,
   `expiresAt` **plus** `renewalOwner` so a licence cannot lapse quietly, and
   `provider` for stock/generated assets.
2. **The crop that eats the subject.** Focal point in normalised coordinates; a
   hero fixed at exactly `(0.5, 0.5)` fails as `focal-point-unchosen`, because the
   centre is where crops are least forgiving and it is what you get when nobody
   looked.
3. **The 1.4 MB hero.** Per-asset allowance **and** a surface ceiling, with the
   sum checked: `weight-budget-exceeded` catches the case where every image was
   "within budget" and the page still ships 4 MB. Zero bytes is valid only for a
   `css-only` asset (`zero-budget-without-css`) — otherwise the field was blank.

## Honest limitations

- **The byte budgets are conventions, not measurements.** 150–250 KB for a hero is
  this project's working default; no benchmark produced it, and the provenance
  catalog has no claim to attach. A project with field LCP data should override
  them and say so — the doc says that explicitly rather than implying precision.
- **Generated-asset licensing is recorded, not resolved.** `provider` keeps the
  training-data/resemblance question visible; it does not answer it, and I did not
  invent a policy for it.
- **Focal points are declared, not verified.** Nothing yet checks that the rendered
  crop actually keeps the point inside the frame; that is a browser check for the
  T0906 wave.
- The module governs decision records only. It cannot stop someone shipping an
  unlicensed image anyway — it can only make the omission visible in CI.
