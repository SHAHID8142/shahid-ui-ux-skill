## What landed — `packages/studio-web/src/selection.ts`

### `SelectionModel` — multi-select with deterministic iteration

- Selection is stored as an **ordered array**, not a `Set`: spatial edits are
  applied in selection order, so iterating a Set would make multi-element
  edits non-reproducible.
- `add` / `addMany` (reports `{added, refused}`), `remove`, `toggle`,
  `rangeTo`, `selectAll`, `clear`. Unknown ids are **refused**, never silently
  ignored — a click that selects nothing must be distinguishable from a click
  that selected the wrong thing.
- `rangeTo` deliberately does **not** move the anchor: repeated Shift-clicks
  grow the range from where the selection started (the behaviour of list and
  file views). The first implementation re-anchored on every call; a test
  caught it and the model was fixed, not the test.
- Constructor rejects an empty universe and duplicate ids.

### `InsertionModel` — markers and the ordered constraint set

- `markers()` returns the `n + 1` gaps in document order with screen-reader
  labels ("Insert between Features and Pricing"), `markerNear(y)` resolves a
  pointer/vertical position to the nearest gap.
- Constructor rejects a section list whose document order cannot be trusted —
  non-ascending `top`, duplicates, invalid geometry. Ambiguity is refused at
  the source rather than discovered later.
- `resolve(index)` → plan with an **ordered** constraint set: `after <prev>`
  then `before <next>` (a single constraint at either end).
- `resolveBetween(a, b)` is unambiguous **only when `a` and `b` are adjacent**.
  When sections lie between them it returns `{ ambiguous: true, candidates }`
  and the draft plan is unconfirmed: the caller must confirm an index
  explicitly (TASKS.json rollback: *"explicit index confirmation"*).
- `confirm(plan, index)` promotes a plan only if the index matches the plan
  **and** `indexFromConstraints` still re-derives that same index.

### `indexFromConstraints` — the invariant that keeps confirmation honest

Re-derives the slot from the constraint set: at most one `before` and one
`after`, both anchors must exist, the pair must be **adjacent**, and the result
must equal the confirmed index. This is what makes a pending plan safe: if the
section list changes under it (the test removes `pricing`), the constraints
stop meaning the recorded slot and the operation is refused instead of
inserting at a stale index.

### `computeSpatialEdit` — atomic multi-element translation

Translates every selected element by one delta and is **all-or-nothing**: if
any point would leave the viewport, nothing moves and the offending ids are
reported. A partial multi-select move is exactly how geometry gets corrupted.
