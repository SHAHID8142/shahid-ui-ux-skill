# T1060–T1074 — the low-severity audit findings (batch receipt)

Batch receipt: one atomic commit covering the low findings from the T1003 audit, plus T1070
(closed by T1047's composer change). T1063 (session expiry/pruning) is **deferred** — see below.

Date: 2026-11-18 · Agent: zcode-audit · Branch chore/continuation-reconciliation

## What changed

- **T1060 (T1003-15)** `packages/eval-core/tests/baselines.test.ts`: the suite binds an ephemeral
  port (`listen(0)` + `server.address().port`) instead of fixed 4345 — the fix T0807 receipted on
  2026-11-14, now landed four days later. Concurrent runs and orphaned workers no longer fail the
  suite with a misleading beforeAll timeout.
- **T1061 (T1003-16)** root `package.json`: verify's chain now runs `typecheck:only`
  (`pnpm -r run typecheck`) instead of `pnpm typecheck` (which rebuilt the whole workspace
  first). With `ensure:built` at the head of the chain and `pnpm build` before the test phase,
  verify now builds the workspace once. The deep bestpractice command timeout was already
  720 s (T1045, the peer's scheduler-timeout fix) — headroom confirmed sufficient by this
  session's suite runs.
- **T1063 (T1003-19)** `packages/studio-bridge/src/server.ts`: the payload caps count bytes —
  `Buffer.byteLength(body)` at the 413 gate and a byte accumulator on the drain cap — instead of
  UTF-16 code units (a multi-byte body up to ~4× the documented 64 KB was accepted).
- **T1064 (T1003-20)** `packages/studio-bridge/src/apply.ts`: the apply engine cross-checks
  `binding.proposalSha256 !== grant.proposalSha256` → refused `grant-mismatch`; a capability for
  proposal A with a grant for proposal B no longer passes both per-side checks.
- **T1065 (T1003-21)** `packages/studio-bridge/src/apply.ts`: `OperationReceipts.assertValidId`
  validates `^[A-Za-z0-9][A-Za-z0-9._-]*$` at `load`, `save` (before the temp-file name embeds
  the id), and `path` — a caller-supplied id can no longer walk receipts out of `.sus/ops`.
- **T1066 (T1003-22)** `pipeline.ts` + `compose.ts`: `fetchHtml`'s truncation reason is carried
  even when the HTML is present; the `seo-structure` detail names "measured a truncated prefix"
  and a needsReview line states that defects beyond the cutoff are unmeasured, not passed.
- **T1067 (T1003-23)** `compose.ts`: the capture and reflow composer branches gain the
  empty-samples guard their siblings have — zero measured combinations/cells read `not-run`,
  never a green pass with "0 captured" in the detail. Unreachable through `runAudit`; it protects
  direct callers of the pure composer.
- **T1068 (T1003-24)** `scripts/lib/gates/g9-semantics.mjs`: absent `clickHandlers`/`focusStyles`
  records fail closed ("not recorded (fail-closed)") instead of defaulting to `[]` and reading as
  clean — "we did not look" is never a pass. Committed fixtures carry the fields; the gate run is
  unchanged.
- **T1069 (T1003-25)** `scripts/check-gates.mjs`: the verdict now states that G12's negatives run
  in the token pipeline test suite (which CI executes as part of `pnpm test`), not in-process in
  this script.
- **T1071 (T1003-27)** `scripts/lib/claims.mjs`: `stripCode` blanks fenced blocks
  line-preservingly — executed check: a violation on physical line 6 after a 3-line fence reports
  line 6 (was line 4).
- **T1074 (T1003-30)** `scripts/gate-push.mjs`: baselines modified **before** the gate are
  preserved (verify's churn is no longer separated from intentional edits by `checkout --`);
  the receipt line names the actually-verified tree — a dirty tree prints that the verified tree
  is not exactly the pushed commit (CI's fresh-clone job re-verifies the pushed commit).
- **T1070 (T1003-26)** — closed by T1047's transition-oracle change (a never-driven route reads
  `not-run` with per-route reasons instead of a parity `fail`); evidence
  `.sus-dev/VERIFICATION/T1047.md`.
