# T1044 — an apply refuses a target that resolves outside the project root

**Found by:** reading the apply path while preparing the audit's §2 (bridge and apply) surface, and asking
what happens if a proposal file path walks out of the tree.
**Branch / base:** `chore/continuation-reconciliation` after T1043.

## Verdict

**Pass**, with the caveat that traversal was **not reachable** through the public API before the fix.

## What was there

`ApplyEngine.apply` resolved targets with `join(this.root, file.path)` and wrote them. Proposal paths are
produced by walking the root, so no public call could inject `../../x` — but nothing in the apply path
asserted containment, and an apply is exactly where the assumption "this path cannot escape" should be
checked rather than believed.

## The guard

```ts
const canonicalRoot = realpathSync(root);
const absolute = resolve(root, path);            // resolve, not join: join concatenates absolutes
const parent = realpathSync(dirname(absolute));  // the parent is resolved…
const canonical = join(parent, basename(absolute)); // …the leaf is not
return canonical === canonicalRoot || canonical.startsWith(canonicalRoot + sep);
```

Two deliberate choices:

- **`resolve`, not `join`.** The first version used `join`, which concatenates, so an *absolute* path was
  glued onto the root, failed `realpath`, and refused a legitimate inside path. The test caught it.
- **The leaf is not resolved.** Resolving the leaf would make a symlinked file look like its target; the
  atomic rename replaces the link instead of following it, so resolving would weaken the guard.

Refusal reason: `path-outside-root`.

## Proof

`packages/studio-bridge/tests/apply.test.ts` — 26 tests, green, including:

| Path | Expected |
| --- | --- |
| `src/card.astro` | inside |
| `src/card.astro/../../escape.ts` | **inside** (normalises to `root/escape.ts`; the guard must not refuse out of caution) |
| `../escape.ts`, `src/../../escape.ts` | refused |
| absolute path inside the root | inside |
| `linked/secret.ts` where `linked` is a symlink out of the root | refused |

`security.test.ts` (capability, provenance, frame and session binding) still green: 58 tests across the
two files.

## Stated limits

- This guard covers the apply path only. Other writers in the repository were not swept, and this receipt
  does not claim a repository-wide path-containment audit.
- `realpathSync` on a directory that disappears between the check and the write throws; the apply then
  fails closed rather than writing.
