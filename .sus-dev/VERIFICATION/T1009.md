# T1009 — ROADMAP.md is a generated view of TASKS.json, and drift fails the build

**Status:** done · **Milestone:** M10 · **Date:** 2026-11-15 · **Owner:** pi (FreePi)

## Why this exists

The repository is public (D34). Its `ROADMAP.md` still described **every** milestone as
`pending` — with `T0101 next` as the active batch — while `TASKS.json` held **100 of 102** tasks
done. A reader deciding whether SUS is usable, or an agent resuming from that page, would have
concluded the build had not started. The M0 row also named `T0001–T0005, T0006, T0007`, omitting
T0009 and T0010.

Hand-written status tables always drift. The fix is not "update the table once" but "make the table
a view, and fail the build when the view disagrees".

## What was built

| File | Role |
| --- | --- |
| `scripts/lib/roadmap.mjs` | Pure functions: milestone scope words, `summariseMilestones`, `statusCell`, `tasksCell`, `renderRoadmapTable/Block`, `parseRoadmapTable`, `checkRoadmap`, `withGeneratedTable`. |
| `scripts/lib/roadmap.d.mts` | Types for the above, matching the `lib/handoff.mjs` convention. |
| `scripts/check-roadmap.mjs` | CLI: check (exit 1 on drift, one line per violation) or `--write` (replace the marked block only). |
| `ROADMAP.md` | Table now sits between `roadmap:table start` / `end` markers and is generated; the "What is left" section states the real position. |
| `packages/schemas/tests/roadmap.test.ts` | 19 assertions: aggregation, rendering, parsing, four drift directions, `--write` scope, and the live file. |

Wiring: `pnpm roadmap` is a script, runs in `pnpm verify` after `pnpm claims`, and in `pnpm
check`.

## Drift directions that fail the build

1. `roadmap-status-stale` — a row's status cell disagrees with TASKS.json.
2. `roadmap-tasks-stale` — a row's task span disagrees with the ids TASKS.json actually holds.
3. `roadmap-milestone-missing` — TASKS.json has tasks for a milestone with no row.
4. `roadmap-milestone-undocumented` — TASKS.json assigns a task to a milestone `MILESTONES`
   does not describe (so a new milestone cannot slip in silently).
5. `roadmap-markers-missing` — the generated block is gone, so nothing can be regenerated.

## Validation, and the mistake it caught first

The first table written by this task was **wrong in three cells** (M1's task span, M10's count,
M10's span). The new checker caught all three on its first run, before it was wired into `verify`:

```
[FAIL] roadmap-tasks-stale — M1 lists "T0010–T0109 (9 tasks)" but TASKS.json gives "T0010–T0104 (9 tasks)"
[FAIL] roadmap-status-stale — M10 says "**7/9 done** — pending: T1003, T1005" but TASKS.json gives "**6/8 done** — pending: T1003, T1005"
[FAIL] roadmap-tasks-stale — M10 lists "T1001–T1009 (9 tasks)" but TASKS.json gives "T1001–T1008 (8 tasks)"
```

## Extension: stale progress figures anywhere in the public surface

While reconciling the roadmap, one more instance of the same class turned up:
`docs/BUILD_COMPLETION_HANDOFF.md` stated "97 of 100 done in `TASKS.json`" (the position at
T1006), and `README.md` still said "no product implementation … was authorized by the audit"
although D28 authorised it on 2026-11-13. So the checker also reads a declared list of
status-bearing documents (`COUNT_CLAIM_FILES`) and fails any `N of M done` figure that disagrees
with TASKS.json — code `count-claim-stale`.

The handoff document was *not* updated to the current number: it describes a past revision, so it
now names no count at all and points at the live source. That is the rule this class needs —
a document describing history must not carry a live figure.

Negative control (temporary edit, reverted):

```
[FAIL] count-claim-stale — docs/BUILD_COMPLETION_HANDOFF.md says "97 of 100 done" but TASKS.json has 101 of 103
```

## What is not claimed

- Prose is not gated beyond the one unambiguous pattern: a document can still be *misleading*
  without stating a number or a milestone status.
- Only the **table** is generated. The narrative sections ("What is left", "Order rationale",
  "Current continuation") are hand-written and not gated; the checker verifies the page's status
  column, not its prose.
- Milestone *scope* words live in `scripts/lib/roadmap.mjs`; if the plan changes wording, that file
  changes by hand. The checker does not compare scope text.
- No new pipeline stage was invented: `pnpm roadmap` sits with the other consistency checkers and
  adds ~0.1 s.
