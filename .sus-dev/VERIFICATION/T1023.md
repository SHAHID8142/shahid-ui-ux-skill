## Refusals, which matter more than the happy path

| Input | Result |
| --- | --- |
| `--scope '#does-not-exist'` | `not-found`, exit 2, no `proposal.json`, "Resolve the scope and run again" |
| `--scope '*'` | `rejected` — "matches the whole page", exit 2 |
| `--scope` a selector matching 5 elements | `ambiguous` with the candidates, exit 2 |
| `--source screenshot --scope-kind region` | `advisory`, exit 2 — pixels are not source |
| `--focus colour` | refused by `parseFocus`, naming the known dimensions |
| quick mode | scope resolves, browser checks are `not-run`, so nothing measured to propose: exit 0 with the untested reasons listed |

## Two defects found while wiring this (fixed here, not worked around)

1. **Findings with the same title collapsed.** `stableFindingId` hashed check, route, viewport and
   title — so two tap targets at the same viewport became one finding and the second lost its
   evidence. Location is now part of the id. Without this, a scoped proposal could report one
   undersized control on a page that has three.
2. **Measured findings carried no measurement.** The overflow, zoom and clipping findings were typed
   `confidence: 'measured'` with only evidence strings, so the proposal contract (correctly) refused
   them as `fact-without-observation`. `PageMetrics` now records `documentScrollWidth` /
   `documentClientWidth`, the clipping probe records `overflowPx`, and all three findings state
   observed vs expected. A measured claim now has a number behind it.

## What this does not claim

- **No slash binding.** Nothing in this repository has run `/sus-bestpractice` inside a host; the CLI
  form is what is verified, and the adapters CLI says so on its own error path.
- **No element-scoped axe.** axe findings are located by rule id, so they are counted as *attributed
  elsewhere* and not proposed for an element scope. Scoping axe to the selection is real work, named
  in T1024 rather than faked by substring matching.
- **No Live Studio selection channel.** A region stays `advisory`.
- **No file-scope attribution.** A `component-path` scope resolves, but the audit attributes findings
  to DOM descriptors, so nothing is proposed against a file until that mapping exists.
