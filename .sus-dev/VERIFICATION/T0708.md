## What actually runs (nothing mocked)

Disposable copy of `fixtures/commerce` (Astro) → sources stamped with anchor
ids → `astro build` → served over HTTP → Chromium with video recording:

1. **Overlay keyboard path.** `CdpOverlay.attach` injects the trusted overlay in
   an isolated world; the demo Tabs until `#sus-overlay-select` is focused,
   presses **Enter**, and asserts `aria-pressed="true"` and the live-region text.
2. **Anchor by keyboard.** Keeps tabbing until an element carrying `data-sus-id`
   is focused — discovered by keys, no hardcoded selector — then
   `resolveSelection` returns confidence 1 **and** `resolveOwner` names exactly
   one source file.
3. **axe over the whole page.** `@axe-core/playwright` on the live page: 0
   violations, 0 serious/critical, 38 rules passing.
4. **The loop.** `applyAstEdit` produces the postimage (real editor) →
   `PreviewSession` proposes and the diff is the bytes that will be written →
   approval → `ApplyEngine.apply` with the stack's own `astro build` as the
   verifier → `applied` → undo restores the preimage **byte-identically** →
   a second undo is refused (`not-applied`).
5. **Evidence bundle** in `evals/evidence/full-loop/<timestamp>/`:
   `manifest.json` (every step with its observed detail) and `loop.webm`
   (65 KB, verified non-zero).

## Three real defects the demo found (and fixed)

- **The overlay's buttons were focusable but inert.** Listeners registered from
  the isolated world never fire for genuine input, so "keyboard navigable" was
  true of focus and false of behaviour. Chrome activation is now bound from the
  main world (`BIND_CHROME`, idempotent per document); bridge *state* stays in
  the isolated world, so the hostile-page guard still holds — and the first
  version of the patch broke that guard, which the T0702 test caught.
- **The overlay live region failed axe contrast.** The status text inherited
  default black on a `rgba(20,22,26,0.92)` bar. Only visible once the status had
  text, i.e. only after the keyboard path worked; fixed by setting the toolbar
  colour. This is why the axe pass must run over the whole page.
- **`page.video()!.path()` returns a Promise**, and my earlier version copied the
  resolved-nowhere path → a 0-byte `loop.webm` that looked like evidence. The
  bundle now records `videoBytes`, and a failed bundle write leaves
  `bundle-error.json` instead of being swallowed.

## Honest limitations

- One stack is exercised end to end here (Astro commerce). The Next fixture's
  chain is covered by T0700wb's feasibility suite, not by this demo.
- The keyboard test proves *an* anchor is reachable, not the specific heading the
  edit targets — a heading is not a Tab stop, and overlay arrow-key selection of
  non-focusable anchors is not yet implemented.
- The video is a browser recording of the DOM, not a narrated walkthrough.
- The loop runs the editor + transaction path directly; the HTTP bridge server
  (T0700wc/T0706) is not in this path, so the demo does not prove the transport.
