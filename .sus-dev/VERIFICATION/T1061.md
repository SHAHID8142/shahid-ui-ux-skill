## What this adds to T1061 (audit finding T1003-16)

The first full `pnpm verify` of the fix wave failed on **4 unhandled `ECONNRESET` errors** from
browser/proxy teardown (component-states + bestpractice command suites) — the same failure class
the audit recorded as T1003-16's "verify not robust", now traced to its root: the authorized
proxy's client sockets had no `error` handlers, so an expected teardown reset crashed the process
as an uncaught exception.

`packages/eval-core/src/harness/authorized-proxy.ts`:
- plain-request path: `req`/`res` error handlers (destroy on reset);
- CONNECT tunnels: `socket.on('error', …)` before any tunnel is established;
- `proxy.on('clientError')` answers malformed/reset client sockets instead of relying on the
  default.

A teardown reset is an expected part of an audit run ending — recorded, not exceptional.
