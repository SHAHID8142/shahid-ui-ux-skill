## The three playbooks and the decision each one is about

**`search-filters`** — the toolbar must *remember*. Query, filters and sort live in
the URL, so a shared link, a refresh and the table→card reflow at 640 px all
restore the same view; typing debounces 250 ms and cancels the in-flight request,
so a stale response can never overwrite a newer one. Long ids truncate in the
middle (the discriminating characters of an id are usually its tail), and a 40 %
longer translated label must not clip the row. Two empties, two actions: *no
records yet — create one* vs *no records match — clear the filters*.

**`settings`** — rarely visited, changed nervously. A permission-gated control is
shown disabled with the role that owns it rather than hidden (hiding it reads as a
missing feature). Saving disables on press, guards the handler and sends an
idempotency key; a failed save keeps every edited value and names the failing
field. Destructive settings live in their own section and never share a save
button with reversible ones.

**`dashboard-widgets`** — instruments, not cards. Each widget loads, fails and
retries **independently**, reserves its final height before data arrives (no layout
shift under a click), and distinguishes zero from no-data, because rendering an
absent measurement as `0` is a lie the operator acts on.
