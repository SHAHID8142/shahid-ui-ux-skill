## Acceptance item by item

**1. Pinned by revision with a retrieval note that states what was and was not used.**
`pin.json` records release `v1.0.0`, revision
`4dd968349e54ca45a05dd5c818fb035c9054b022`, Apache-2.0, and four guide paths — and
`sha256: null` / `verified: "unverified"` for all of them, with a `verificationNote`
that says the pin came from **owner triage in issue #14**, not from a fetch by this
toolchain, and that no digest was computed and no guide text is quoted anywhere. The
`notPinned` list names both things that are *not* covered: the other ~250 guides, and
the upstream tooling (search/retrieve/legacy-scan/install), which is pinned nowhere
and run nowhere. The provider refuses to emit a hit from an unverified pin, so the
unverified record cannot silently become evidence.

**2. The guard is recorded and checkable; telemetry/offline stated, not assumed.**
`checkResponsiveTable({css, markup?})` returns five checks — `pseudo-label-pattern`,
`header-stays-in-a11y-tree`, `overflow-not-concealed`, `cell-labels-complete`,
`label-order-matches-header` — and its 22 tests prove it against the real
`fixtures/admin` pair (pass), against seven mutated copies (each fails a *named*
check), and against both pilot pages. Getting those 22 tests to pass found two real
defects in the guard, fixed in this task:

- `pseudo-label-pattern` only matched `content: attr(data-label)` exactly, so the
  anti-pattern's own `attr(data-label) ': '` decoration read as "no pattern" and
  skipped the header check entirely — the guard would have passed the very page it
  exists to reject. Now any rule that paints the attribute counts.
- A table using neither half of the pattern (no `data-label`, no painted label) was
  reported **fail**; it is out of scope, and it now reports `not-applicable`.

Telemetry and network are stated in `docs/RESEARCH_SOURCES.md` §9 and enforced in
`research-provider.ts`: no analytics, no telemetry, no background calls; the online
arm requires `SUS_RESEARCH_ONLINE=1`, and the offline path returns `available: false`
with `loaderCalls: 0` rather than an error. Caps are constants, not conventions:
`RESEARCH_MAX_QUERY_WORDS` / `MIN`, `MAX_HITS_PER_QUERY`, `MAX_EXCERPT_CHARS`,
`MAX_CALLS_PER_RUN`, and `RESEARCH_SUPPORTED_LICENSE = 'Apache-2.0'`.

**3. At least three pilots with measured before/after.**
Three pairs under `evals/research/modern-web-guidance/pilots/`, driven in Chromium at
390 px through `ariaSnapshot()`, document-overflow, axe serious/critical and
`runHardeningMatrix` (3 viewports x 2 themes x 2 motion):

| Pilot | Instrument | before | after | negative / fallback |
| --- | --- | --- | --- | --- |
| responsive-table | `columnheader` count | **0** | **4** | forced `display:none`: 0; at 320 px: 4 |
| navigation-drawer | contract flags from the snapshot | `aria-expanded` absent, focus not moved, 4 tab steps behind the drawer, Escape does not close, focus not returned, 0 links without JS | all six true/0, `noJsVisibleLinks` 4 | drawer never opens: not-run |
| inp-handler | long tasks on the performance timeline | 1 task, 360 ms max, 310 ms blocking | 0 tasks, 0 ms blocking | timeout fallback: 0 ms blocking |

Every pilot is a `before.html` / `after.html` pair that is served from disk by the
harness, so the numbers are reproducible with `pnpm pilots` and the digests in
`results.json` guard against editing a page after measuring it.

**4. No vendor, no execution, no claim beyond the measurement.**
Nothing from upstream is copied into the repository; `pin.json` quotes no guide text;
the provider is an interface with an injected loader, so no network client, CLI or
runtime is executed. `COMPATIBILITY.md` §6 and `pilots/README.md` state the limits
inline: headless Chromium only, `en` locale, synthetic pairs, browser-timeline timings
rather than field INP, and the provider arm is **not-run** because upstream was never
fetched. A source-text `pass` from the guard never means assistive technology works —
that sentence is in the module header, the receipt and the docs.

## Honest limitations

- **The pin is unverified.** `sha256: null` everywhere, so the provider arm is
  `not-run` end to end. Issue #14 asks for paired tasks with and without a provider;
  the *without* half is the shipped one, and the *with* half is exercised only through
  an injected fake loader in the 27 provider tests. A real fetch needs a run under
  `SUS_RESEARCH_ONLINE=1`, which has not happened.
- **Generated content is not nothing.** In the `before` page the 16 cells keep their
  label text in the accessible name, so only the `columnheader` count exposes the
  break. The receipt and the docs say this rather than claiming the labels vanish.
- **The guard is a text heuristic.** It does not resolve the cascade, evaluate media
  queries or observe a browser; it reads the technique. The browser measurement is the
  evidence, the guard is the regression trap.
- Three pilots out of ~254 guides; four guides pinned out of them. Coverage here is
  exactly what was measured, not a fraction of upstream that has been reviewed.
