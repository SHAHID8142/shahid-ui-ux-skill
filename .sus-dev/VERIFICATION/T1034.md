# T1034 — a demo run no longer prints git's complaints (issue #21 R9)

**Task:** issue #21 R9: `pnpm demo:loop` printed `fatal: not a git repository` from a git call inside a
temp fixture. Harmless, and it read like a failure.
**Approval:** D32 issue triage inside D28; the owner's `go ahead` on the R-series.
**Branch / base:** `chore/continuation-reconciliation` at `956b50f`.

## Verdict

**Pass.** `gitSnapshot` still answers "unknown" for a non-repository, and no longer writes git's
complaint to the terminal.

## Cause

`packages/studio-bridge/src/apply.ts` ran `git rev-parse HEAD` and `git status --porcelain` with
inherited stderr. The failure was already handled through the throw (the function returns `null`), but
git had already printed `fatal: not a git repository (or any of the parent directories): .git` to the
demo's terminal — an expected answer shown as an error.

## Fix

Both calls pass `stdio: ['ignore', 'pipe', 'ignore']`, so stdout is read and stderr is not inherited; a
non-repository throws exactly as before and is recorded as `null` / "unknown". Failure detection is
unchanged, so nothing is hidden that was previously visible in the receipt — the receipt only ever
recorded `null`, never git's text.

## Proof

- `pnpm demo:loop`: exit 0, and `grep -c "not a git repository"` over its output = **0**.
- `packages/studio-bridge/tests/bridge-launcher.test.ts` (test 5): a probe process calls
  `gitSnapshot(<temp dir outside any repository>)`; stdout is `null` and stderr is **empty**.

## Stated limits

- Only the snapshot call is quieted; the tests that intentionally `git init` a temp fixture still use
  git normally, with output going where it is expected.
- Nothing about the apply/undo transaction, its receipts or its verification changed.
