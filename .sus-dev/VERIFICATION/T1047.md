# T1047 — a partially measured route set never reads as a clean states/motion check (audit finding T1003-2)

Date: 2026-11-18 · Agent: zcode-audit · Branch chore/continuation-reconciliation

## What changed

`packages/eval-core/src/audit/compose.ts`, two composer branches:

- **transition-oracle** (else-branch): now reads `inputs.motion.failed` (routes whose probe errored
  were dropped on the floor before), names the not-driven routes (route + reason, not just a count
  of reasons), and computes status as `fail` only when a verdict actually failed; unmeasured or
  errored routes without a failing verdict read `not-run` with the per-route reasons (this also
  lands audit finding T1003-26 / T1070: a never-driven route is an incomplete measurement, not a
  parity failure).
- **component-states** (else-branch): not-run samples and `states.failed` routes are now named in
  the detail and keep the check at `not-run` (with a reason, as the report schema requires); a
  measured defect still reads `fail` even when other routes are unmeasured; the honest-pass note
  only attaches to a real `pass`.

## Why

Audit finding T1003-2 (high, reproduced against the built composer): a mixed route set — one route
clean, one route with no drivable control (`not-run`), one probe error — emitted green `pass` for
both checks while naming only the routes that happened to measure. The zero-measured branches
already named their reasons; the mixed runs went quiet, and both checks are `required: false`, so
exit 0 was reachable on evidence that was never taken.

  measured hover defect with an unmeasured route → `fail` with the finding pushed; motion mixed run

  partial clean motion run → `not-run` (the T1003-26 direction).

- Negative control by construction: the old code cannot pass the first and fifth new tests (it
  returned `pass` for the mixed states group and buried `/about` as a count of reasons).

## Note
