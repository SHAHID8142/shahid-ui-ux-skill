# T1040 — a native `details/summary` disclosure is driven too

**Task:** the second interaction shape. T1036 could only drive an element declaring `aria-expanded`, so a
page using the platform's own disclosure would have been `not-run` forever — the same "unmeasured reads as
absent" problem in a different place.
**Branch / base:** `chore/continuation-reconciliation` after T1039.

## Verdict

**Pass.** The probe picks a disclosure in two steps: a hand-rolled `[aria-expanded]` widget first, then a
native `details > summary`. Both shapes are driven in all three contexts (pointer, keyboard, reduced
motion), and the traces go to the same oracles.

| --- | --- | --- |
| `fixtures/bestpractice/motion` | `button#toggle[aria-expanded]` | pass |
| `fixtures/bestpractice/motion-details` | `details > summary` | **pass** |
| `fixtures/bestpractice/motion-details-lost` | `details > summary`, content hidden under reduced motion | **fail** — `reduced-motion-information-lost` |
| `fixtures/bestpractice/scoped-axe` | neither | not-run, reason names both shapes |

## What the shape changes, and what it does not

- State: `details.open` → `open` / `closed`, instead of the `aria-expanded` attribute value.
- Keyboard: `Space` for a native summary (what the platform binds), `Enter` for the `aria-expanded` widget.
- Text and visibility: the `details` element's `innerText` and `checkVisibility()` — unchanged rule, because
  information parity is what is compared (kilo M2), not CSS.
- Trigger descriptor: `details > summary "Shipping options"`, so a report names what was driven.

## Proof

`packages/eval-core/tests/motion-probe.test.ts` — 6 tests, green, including the two new ones: the native
disclosure passes parity, and the lossy native one fails with the same oracle rule as the `aria-expanded`
fixture. Both fixtures differ in exactly one thing (whether reduced motion keeps the text), so the test is
about the measurement rather than the CSS.

## Stated limits

- Still **one** disclosure per route, and no hover-only, carousel, drag or scroll-linked animation.
- `dialog`, `popover` and custom accordions that keep state in a class rather than an attribute are not
  driven: there is no generic signal to read.
