## What landed

`FindingsOverlayStore` (DOM-free, `packages/studio-web/src/findings-overlay.ts`)
consuming the **landed** `@sus/scanners` contract (`Finding`/`ScanResult`,
T0304) — no second scanner, no duplicated finding type:

- **Source-linked findings.** Every finding carries `file`, `line`, `snippet`,
  `locator` (`file:line`) so the overlay can render it in source context.
- **Suppression requires a recorded reason.** `dismiss(key, reason)` is refused
  for: unknown key, already-dismissed key, and any reason shorter than
  `MIN_DISMISSAL_REASON_CHARS` (12) after trimming. A suppression without
  justification is the alert-fatigue failure mode this task exists to prevent.
  `restore(key)` reverses a decision.
- **Content-fingerprint identity, not line identity.** Dismissal keys are
  `category|file|folded-snippet|folded-matched` (+`#n` for repeated identical
  occurrences). Editing an unrelated line ABOVE a finding shifts its line
  number without resurrecting it; a *different* finding in the same file never
  inherits a dismissal. Documented limitation: if the first of two identical
  occurrences is fixed, the second becomes `#1` and inherits its dismissal —
  recorded in the source comment, surfaced by `staleDismissals()` when it
  matters.
- **Re-scan replaces findings, preserves decisions.** `ingest(results)` swaps
  the finding set and re-applies dismissals by key. Dismissals whose finding
  vanished are reported by `staleDismissals()` and flagged in the log — never
  silently deleted, never silently kept.
- **Dismissal log in DECISIONS.md's own format.** `dismissalLogLines()` emits
  append-only rows matching the `DECISIONS.md` header
  (`date | decision | rationale | alternatives | approval | scope`), escaped so
  a `|` or newline in a reason cannot break the column format. The store does
  **not** write the file: applying those rows is an approval-gated write
  (T0706/T0707), same rule as any source mutation.
- **Alert-fatigue rollback lever.** `DEFAULT_SEVERITY_FILTER` is a single named
  constant (`'all'`); the documented rollback for the stated risk
  ("alert fatigue") is flipping that constant, not rewriting the overlay. The
  filter never changes dismissal state; `counts()` separates `dismissed` from
  `filteredOut`.
