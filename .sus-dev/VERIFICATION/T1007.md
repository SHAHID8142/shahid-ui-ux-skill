## What the owner asked for, and what this changes

Issue #10 rejects "desktop tabular rows that overflow horizontally on mobile" and requires a
content-driven transformation (records become readable stacked cards), not shrink-to-fit, and
forbids concealing overflow with `overflow-x: hidden`. T0906 then *measured* two failures on
our own reference dashboard and deliberately left them: F1, 343px of document-level horizontal
scroll at 390px; F2, muted text at 4.46:1 (0.04 below AA).

Both are fixed here, in the fixture that is the SUS-guided reference implementation:

| Finding | Change | Why it was failing |
| --- | --- | --- |
| F1 reflow | `#admin-shell` track `1fr` → `minmax(0, 1fr)`; sidebar becomes a wrapping top bar ≤52rem; the queue becomes self-labelled block cards ≤40rem (`td::before` prints each cell's `data-label`) | A `1fr` grid track cannot shrink below its content's min-content width, so the five-column table pushed the document wider; with no media query the only narrow layout was a squeezed table |
| F2 contrast | `--muted: #5f6775` (5.28:1 on `--bg`, 5.70:1 on `--panel`) replacing the `#6a7284` literal (4.46:1) | A near-miss is a fail and is invisible in review — only measurement finds it |

One DOM, two layouts: no duplicated presentation, no second copy for a screen reader to meet
twice, and the `<thead>` stays in the accessibility tree instead of being removed with
`display: none`. The narrow layout prints the same five labels in the header's order.

## Bootstrap defect found and fixed

`pnpm setup` — the command `AGENTS.md` and `docs/RESUME_ON_NEW_MACHINE.md` tell a fresh machine
to run first — could never install Chromium: `pnpm exec playwright` at the workspace root fails
with `Command "playwright" not found`, because playwright is a dependency of `@sus/eval-core`
and `@sus/studio-bridge`, not of the root. It is now
`pnpm --filter @sus/eval-core exec playwright install chromium`, and both documents say so.
This was found by following the documented bootstrap on this machine and getting exactly the
failure the document says will not happen.

Known cosmetic issue, recorded rather than hidden: `pnpm setup` now prints
`[ERROR] Unknown option: 'verify-deps-before-run-install'` followed by a
`[WARN] The install that runs before scripts failed` line before the three real steps run and
succeed (`machine ready: …`). It comes from pnpm 11's pre-run dependency check inside a nested
`pnpm` call, not from the script's own commands; `pnpm hooks:install` alone shows no warning.
Exit code is 0 and every step performs its work, so this is a message to fix in a later
tooling task, not a broken bootstrap.
