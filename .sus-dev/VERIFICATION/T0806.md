## What landed

### `docs/THREAT_MODEL.md` — the artefact the evidence is produced against

Assets, trust boundary, and **T1–T11 threat → control → test** rows covering
every acceptance bullet: page token reads, synthetic approval, UI replacement,
cross-frame confusion, navigation/reconnect replay, direct commands, DNS

model forbids adding a capture path before it is).

### `src/security.ts` — real enforcement, not assertions

- **`ActionBoundary`** (DA-31): only `user-typed`/`user-drawn` provenance can
  authorise a `write`/`command`/`network`. Page DOM, page scripts, OCR,
  screenshots, recalled lessons and annotation labels are data. Ordering is
  deliberate and tested: untrusted provenance is refused **before** the
  capability is even examined, so a page that somehow learned a capability id
  still cannot act, and a denied request does not burn the user's capability.
- **`CapabilityAuthority`**: single-use capability bound to session + frame +
  action kind + proposal hash + worker fence + TTL. Every mismatch has its own
  deny reason; consumption is recorded so replay denies instead of silently
  repeating. Issuance refuses a blank approver and an unknown action kind.
- **`minimizeCapture`**: masks form values (keys kept, values gone), record
  lines, bare person-name lines, emails, phones, cards and secret assignments;
  records only aggregate counts, never removed values; `consentRequired: true`
  so the exact redacted payload is shown before consent. Conservative by
  construction — the contract forbids assuming unmarked means public.
- **`CaptureStore`**: typed to accept only a `RedactionResult` (raw strings are
  unimplementable), per-record retention with `purgeExpired`, plus
  `deleteSubject` and `revokeConsent` that delete immediately.
- **`evaluateG13`**: `not-run` without evidence, `fail` on any undefended
  attempt / residue / skipped consent / failed deletion / open critical,
  `pass` only when all hold, and **`not-applicable` is refused outright** —
  `waivable: false` is in the verdict type.

### `src/server.ts` — one real defect fixed

`start()` resolved the *configured* port, so `port: 0` reported 0 while the
server listened on an ephemeral port. It now resolves `server.address().port`.
This is what the peer's earlier port-collision finding (orphaned suite holding a
fixed port) needed: the security suite binds an ephemeral port and can never
collide with a peer's run.

### Gate wiring — G13 is now implemented and its negatives are executable

`check-gates.mjs` imports the built `evaluateG13` and proves in-process: no
evidence → `not-run`; one undefended attempt → `fail`; redaction residue →
`fail`; retained material → `fail`; a `not-applicable` claim → `fail`; fully
defended evidence → `pass` with `waivable === false`. A registry edit alone can
no longer make this gate pass. A dedicated CI job (`security`) runs the hostile
suite and the gate negatives separately from `verify`, so a denial failure
cannot read as "one red step among many".

## Honest limitations

- The hostile attempts are proven at the **boundary layer** T0707 will call, not
  over an HTTP apply route — that route does not exist yet and the threat model
  says so. When it lands, the same checks must run before the first mutation.
- Redaction is text-level. Screenshot/OCR image redaction is unimplemented, and
  the model forbids adding a screenshot capture path before it exists.
- `T9` retention duration is a product-policy value; the code takes it as
  configuration and capture remains disabled until policy sets it.
- The audit log has no size bound yet (append-only in memory); durable audit
  persistence is a bridge-server concern outside this task and is recorded here
  rather than silently assumed solved.
