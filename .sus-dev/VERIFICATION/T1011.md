# T1011 — The documented first-run path is verified on Linux, continuously

**Status:** done · **Milestone:** M10 · **Date:** 2026-11-15 · **Owner:** pi (FreePi)

## Why

T1010 fixed a defect that only existed for a pristine clone, and the reason it survived so long is
visible in the pipeline: the `verify` CI job runs

```yaml
- name: Build (dist for cross-package gates/typecheck)
  run: pnpm build
- name: Continuation checker
  run: pnpm check
```

That build step is correct for a warmed checkout and is exactly what **hid** the defect: CI never
exercised the path `docs/RESUME_ON_NEW_MACHINE.md` tells a person to follow. Fixing T1010 without
adding this job would leave the same blind spot one refactor away — and the platform claim (macOS
only) would stay open, since CI's Linux runs all pre-build.

## What was added

A fourth CI job, `fresh-clone`, which:

1. clones **the same commit** out of the checkout into `$RUNNER_TEMP/fresh`
   (`git clone --quiet --local --no-hardlinks .`), then asserts the tree has no `node_modules` and
   no `packages/eval-core/dist` — a tree that has never been built;
2. installs browser libs (`playwright install --with-deps chromium`) — environment, not repository
   state;
3. runs **exactly** the documented three commands: `pnpm install --frozen-lockfile`, `pnpm setup`,
   `pnpm verify`.

The job carries a comment saying not to add a build step to it: if this job is red, the documented
path is broken, and "fixing" it with `pnpm build` restores the blind spot.

A `git archive` extraction was rejected as the mechanism: an archive has no `.git`, so
`pnpm setup`'s `git config core.hooksPath` fails and `check-continuation.mjs` cannot read a revision.
A local clone gives a pristine *working tree* that is still a git repository.

## First CI run: the job found its own bug (run 43750351930)

The job went red on its first Linux run, on the step before the documented path:

```
[ERR_PNPM_RECURSIVE_EXEC_FIRST_FAIL] Command "playwright" not found
```

The browser-libs step was running `pnpm --filter @sus/eval-core exec playwright …` **in the warmed
checkout**, where nothing had been installed — the exact failure `RESUME_ON_NEW_MACHINE.md` §2.1
documents. The step now runs inside the fresh tree, after its own `pnpm install`. The same run also
showed `warning: source repository is shallow, ignoring --local`, so the fresh-clone job's checkout
uses `fetch-depth: 0`: a shallow copy is not what a person gets from `git clone`.

Both were caught by the job rather than by a reviewer, which is the point of adding it.

## Guards

Three assertions in `packages/schemas/tests/ensure-built.test.ts` keep the job honest:

- the job exists and contains the clone, the "never been built" assertions, `pnpm setup` and
  `pnpm verify`;
- the job contains **no** `run: pnpm build` (the step that hid the defect);
- the warmed `verify` job *does* still build first, which is correct for it.

## Not claimed

- The job runs on `ubuntu-latest` with Node 22 only. Node 24 is covered by the `verify` matrix, not
  by the fresh-clone job (one fresh-clone lane is enough to catch a missing build step).
- Windows was not rehearsed and is not claimed.
- The job costs ~5 minutes per push; it does not replace the warmed `verify` job, which is faster
  because it can reuse a build.
