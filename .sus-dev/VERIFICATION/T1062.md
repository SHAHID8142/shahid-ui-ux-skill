# T1062 — bridge session expiry (audit finding T1003-18, issue #25)

Date: 2026-11-19 · Agent: zcode-audit · Branch chore/continuation-reconciliation

## What changed

The finding was deferred by the fix wave with owner sign-off required; the owner then directed
work on all open issues (#25 explicitly offers "fix or explicitly restrict"), so the fix is
implemented rather than deferred:

- `packages/studio-bridge/src/server.ts`:
  - `SessionPolicy` on `BridgeOptions` — **absolute TTL** (default 24h), **idle TTL** (default
    30min, renewed on every successful authenticated request), **max retained sessions** (default
    16) and an **injectable clock** (`sessionPolicy.clock`).
  - `verifyToken` enforces both deadlines fail-closed: an expired or idle-expired session is
    closed, audited (`session-expired`) and deleted before any HMAC comparison outcome matters.
  - `openSession` prunes expired sessions and evicts the **least-recently-used** session at the
    cap (`session-evicted` audit event) — a leaked token cannot hold a slot by never being used.
- `scripts/studio/bridge.mjs`: the printed token line now states the real policy instead of
  "valid until this process exits".
- The five-minute capability TTL in `security.ts` is a DIFFERENT control (privileged operations)
  and is unchanged — the issue's own non-conflation requirement.
