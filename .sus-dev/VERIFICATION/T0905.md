## "Never hand-edited" needed a mechanism, not a comment

`pnpm support` regenerates both files in memory and fails when the committed
bytes differ, and it runs **after** `pnpm build` inside `pnpm verify` — so it
compares against the artifact that just got built. Editing the table by hand now
fails CI on the next run instead of surviving until someone notices.

## What a row binds

Every row records: the **artifact id and SHA-256** (manifest + built entry points
only — reformatting a comment must not invalidate a smoke run), the **environment**
(host version, browser, framework, OS), the derived tier from capabilities
(T0901), and its smoke evidence reference with the hash that evidence was produced
against.

## Invalidation is the point

`evidenceState()` compares hashes, never dates: a package rebuilt yesterday from
unchanged sources is the same artifact, and one rebuilt today from changed sources
invalidates evidence even though it is newer. A `supported` row whose evidence is
stale is **downgraded to `experimental`**, and both tiers are recorded so the table
shows what happened rather than quietly keeping the old claim. A receipt written
before artifact binding existed carries an empty hash, which can never equal a real
one — so it reads as stale.

Real state after this task: `freepi` verified against the current artifact
(smoke re-run on this host, 7/7 PASS); `zcode` **stale** (its receipt predates
binding); `codex`, `claude-code`, `cursor` have no smoke evidence at all. No row is
`supported`, because Live Studio is unexercised everywhere — which is the honest

## Honest limitations

- **Evidence is machine-local.** The freepi receipt was produced on this machine;
  host version is `unrecorded` because the smoke script has no reliable way to ask
  a host its version. Recording it as `unrecorded` is truthful; inventing `26.0.1`
  would not be.
- **Live Studio is unverified on every host**, so no row reaches `supported`. The
  tiers are what was tested, not what probably works.
- **Browser/framework are `n/a`** in this run: the smoke script does not open a
  browser or build a fixture. Those columns fill in when the T0906 wave runs the
  browser-side checks.
- The artifact hash covers the built adapter package only; skill content changes do
  not invalidate host evidence, which is a deliberate scoping choice, not an
  oversight.
