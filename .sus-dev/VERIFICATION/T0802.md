## The failure this prevents

The dangerous failure of a mapping studio is not "the edit did not apply" — it is
"the edit applied somewhere else": the anchor survived in a different element, the
section moved, or the user edited the file after the overlay was drawn. Each
produces a *plausible* write that silently damages the product.

`MappingConflictSession` therefore never repairs. It classifies:

| Kind | When |
| --- | --- |
| `file-changed` | the file's bytes differ from the hash recorded with the annotation — checked *even when the anchor still resolves*, because the two edits were never reconciled |
| `anchor-missing` | nothing declares the anchor any more |
| `anchor-duplicated` | the anchor now appears more than once in the file |
| `owner-changed` | the anchor resolves to a different file than the one recorded — refusing to retarget silently |
| `ambiguous-owner` | the index itself cannot pick one owner |
| `file-deleted` | the file is gone |

Ordering is deliberate: the byte-hash check runs before anchor resolution, so a
user edit is reported as `file-changed` rather than being re-mapped onto their
new code. Two tests had to record the mutated hash to isolate the later paths —
that is the ordering working, and the tests now say so.

## What the user is offered

Exactly two honest actions per conflict — `retry` and `export` — with no silent
third option:

- `retry` re-reads the tree and re-checks. It is not a bypass: if the anchor is
  still gone, the retry still conflicts (tested).
- `exportBundle()` hands back a versioned bundle containing **every** annotation
  verbatim (note, region, timestamp, recorded hash) plus every conflict, and a
  `retryAvailable` flag. Nothing is rewritten on the way out.

`preserved()` and the export test assert byte-for-byte equality of the annotation
object, because "preserved" is the acceptance criterion and a summarised
annotation is not preservation.

## Honest limitations

- Staleness is detected by file content hash, so a formatting-only change also
  conflicts. That is intentional (cheap, conservative) but it means a formatter
  run invalidates pending annotations; the user's remedy is `retry`, not a merge.
- The session indexes only the files the caller lists (`SourceTree.files`); an
  anchor moved into a file outside that list reads as `anchor-missing`, not
  `owner-changed`.
- No merge or three-way reconciliation is attempted, by design: merging a user's
  concurrent edit with an approved proposal is a decision that needs the user,
  and the protocol here is to hand it back.
