## Corrections demanded by the #19 Codex comment

1. **`docs/QUICKSTART.md` (and the same pattern in `docs/RELEASE_NOTES_v0.1.0-preview.1.md`)**:
   the preview-tag checkout and the development-branch checkout sat in ONE executable block, so a
   reader copying all commands ended on whichever `git switch` ran last. Both files now carry the
   shared clone step and two clearly labelled **mutually exclusive** blocks (Option A: tag,
   "only valid once the owner publishes"; Option B: development branch), with an explicit
   statement that **`v0.1.0-preview.1` does not exist as of 2026-11-20** — nothing claims the
   uncreated tag exists.

2. **`docs/THIRD_PARTY_NOTICES.md`**: the old wording ("dev dependencies … not installed by
   consumers"; `sentry` "never reaches a SUS user's install") was wrong for the documented
   install path — a source checkout's plain `pnpm install` installs devDependencies too. The page
   now distinguishes:
   - **Production/runtime dependencies** (285 packages, `pnpm licenses list --prod`): what
     SUS's own packages execute and what a hypothetical distributed artifact would carry;
   - **Source-install footprint** (503 packages, `pnpm licenses list`, all environments): what
     the documented source install actually downloads, including the dev-only rows —
     FSL-1.1-Apache-2.0 `sentry` (via lighthouse; the "never reaches" claim is corrected
     explicitly), MIT-0 `@csstools/*` tooling, and the PSF-2.0/Python-2.0 `argparse` dual tag.
   Both tables re-measured on the candidate tree (2026-11-20); the page keeps its
   regenerate-per-release rule.
