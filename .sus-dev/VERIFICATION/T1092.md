# T1092 — issue #32: malformed unauthenticated JSON must not escape the Studio bridge request handler

Date: 2026-11-20 · Agent: `sus-release` (darwin/SSD) · Branch: `release/v0.1.0-preview.1-prep`
Fix commit: `a91424e` (on top of the dev-integration merge `9e74bbf`, task records `bd84826`)

## Finding (Codex preliminary review, read-only)

`handleMessage()` JSON-parsed the request body and read `(parsed as {sessionId?: string}).sessionId`
without validating the top-level shape. `null` is valid JSON; reading `.sessionId` off it threw a
`TypeError` **before token verification**, and `req.on('end')` had no catch, so the exception
escaped the per-request handler. Codex reproduced the handler-level exception in memory; process
termination and remote exploitability were explicitly NOT asserted, and this fix does not assert
them either.

## Fix

- Top-level shape validation before authentication: `null`, arrays, strings, numbers, booleans →
  stable **400** `invalid-shape` with a bounded `message-rejected` audit entry naming the shape
  only (`non-object JSON body (null)` etc.) — never the body content.
- **Status ordering deliberate and documented in code:** shape rejection (400) happens before the
  token check; a structurally acceptable envelope with a bad/missing token keeps **401**
  `auth-denied`.
- `req.on('end')` wraps the handler in a catch: any unexpected exception answers with an
  intentional bounded response (500 `handler-failure`, audit `handler-failure` — event added to
  the `AuditEntry` union), never hangs the connection, never logs body content or secrets.

## Tests (real HTTP, loopback bridge, ephemeral port — not in-memory probes)

`packages/studio-bridge/tests/server.test.ts` grew 16 → **31 tests**, all passing:

- Boot on an ephemeral port; authenticated ping control → 200.
- Unauthenticated `null`, `[]`, `true`, `1`, `"text"`, malformed `{"sessionId":` → 400/413 as
  appropriate; after **every** payload the server is still listening and an authenticated request
  succeeds (bridge remains operational — asserted per case).
- Shape rejections audited: exactly one `message-rejected` per payload, details naming the shape,
  none echoing hostile content.
- Structurally acceptable envelope with a bad token → 401 (ordering proof).
- Oversized body → 413; bridge keeps serving.
- Authenticated valid envelope → 200 with a `message-ok` audit entry.

The `null`-over-HTTP case genuinely pins the fix: without the shape guard the request would return
500 (`handler-failure` via the new boundary catch) instead of the asserted 400.
