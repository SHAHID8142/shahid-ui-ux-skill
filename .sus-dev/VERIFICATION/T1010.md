# T1010 — A pristine clone can run the documented first-run commands

**Status:** done · **Milestone:** M10 · **Date:** 2026-11-15 · **Owner:** pi (FreePi)

## How this was found

Not by reading code. A real clone of the public repository was made into `/tmp/sus-fresh` and the
documented resume path was followed exactly as `docs/RESUME_ON_NEW_MACHINE.md` states it:

```bash
git clone -q --branch chore/continuation-reconciliation https://github.com/SHAHID8142/shahid-ui-ux-skill.git
pnpm install --frozen-lockfile     # exit 0, 23.6s
pnpm setup                         # exit 0 — but printed a false "[ERROR]"
pnpm verify                        # exit 1
```

Every one of those results was invisible on the working copy, where all four steps had been green
for days: the working copy's `packages/*/dist/` directories predated the clone. **The documented
path only ever breaks for the person the document was written for.**

## The four defects, in the order a new machine meets them

| # | Observed | Cause | Fix |
| --- | --- | --- | --- |
| 1 | First `pnpm run <script>` printed `[ERROR] Unknown option: 'verify-deps-before-run-install'` and `[WARN] … your node_modules may be out of sync` before running correctly | pnpm 11.22.0's pre-run dependency check passes its own flag to `pnpm install`, which rejects it | `verifyDepsBeforeRun: false` in `pnpm-workspace.yaml`, with the reason written where someone would look for it |
| 2 | `pnpm support:status` → raw `ERR_MODULE_NOT_FOUND` stack trace | `generate-support.mjs` imports `packages/adapters/dist/index.js` | loads compiled packages only after an explicit artifact check; prints the command to run instead of a trace |
| 3 | `pnpm verify` → `ERR_MODULE_NOT_FOUND … packages/eval-core/dist/index.js imported from scripts/check-gates.mjs` | `check-gates.mjs`, `check-direction.mjs`, `generate-support.mjs` import compiled packages; nothing built them | `scripts/ensure-built.mjs` builds once when an artifact is missing; wired as the first step of `pnpm check` and `pnpm verify` |
| 4 | `docs/RESUME_ON_NEW_MACHINE.md` promised "expect: 64 files, 679 tests" | the figure was true in November and cannot stay true | the document names no count; the checker refuses the pattern (see below) |

## Why the fix is a guard rather than a step in the document

Adding "run `pnpm build` first" to the document would fix it until the next person skips a line.
`ensure-built.mjs` is a no-op when the artifacts exist (66 ms measured) and one `pnpm build` when
they do not, so the documented three commands stay the documented three commands. `pnpm verify`
still runs a full `pnpm build` afterwards, so the guard cannot mask a genuinely broken build — a
test asserts both properties.

`REQUIRED_ARTIFACTS` lives in `scripts/lib/ensure-built.mjs` with a test that pins each entry to the
`packages/*/dist/index.js` shape and to the three packages the scripts actually import, so a seventh
compiled package cannot be forgotten silently.

## The unverifiable-figure rule (part of T1009's checker)

`count-claim-unverifiable`: a test or file **count** cannot be checked from the repository at build
time — it changes with every commit — so a document stating one is stale the moment it is written.
The checker refuses it instead of comparing it. Negative control (temporary edit, reverted):

```
[FAIL] count-claim-unverifiable — docs/RESUME_ON_NEW_MACHINE.md states a test/file count
("expect: 64 files, 679 tests"), which no build step can keep true — point at the command's own summary instead
```

## Fresh-clone rehearsal of the fix

Cloned the repository from its local path at the fix commit into `/tmp/sus-fresh2` (same tree the
remote would serve), then ran the three documented commands.

```text
$ git clone -q --branch chore/continuation-reconciliation /Volumes/SSD/CODES/SUS sus-fresh2
$ git log --oneline -1
f4aa598 fix(build): a pristine clone can run the documented first-run commands

$ pnpm install --frozen-lockfile
Done in 2.7s using pnpm v11.22.0                                  # INSTALL=0

$ pnpm setup
$ git config core.hooksPath .githooks && pnpm --filter @sus/eval-core exec playwright install chromium && …
machine ready: push gate installed, chromium present, recorded state consistent   # SETUP=0, no [ERROR]

$ pnpm verify
[INFO] 7 build artifact(s) missing — building once before the checks run
… Test Files  70 passed | 3 skipped (73)
  Tests  749 passed | 5 skipped (754)                             # VERIFY=0
```

The same walk on the pre-fix commit gave `VERIFY=1` at `gates:full` with
`ERR_MODULE_NOT_FOUND … packages/eval-core/dist/index.js`, plus the `[ERROR]` line in the `setup`
output and the stack trace from `pnpm support:status`. The guard printed exactly one line before
building, which is what a person should see: the build is happening, and why.

## Not run and not claimed

- Only macOS arm64 was rehearsed. A Linux or Windows fresh clone was not run; the artifacts are
  JavaScript and shell-free, but the claim is limited to what was executed.
- The rehearsal used a local clone of the same commit rather than a second network clone, because
  the fix was not yet pushed; the remote SHA is recorded in `.sus-dev/STATE.md` once it is.
- `pnpm setup` still delegates to pnpm's own install machinery; `verifyDepsBeforeRun: false` removes
  a misfiring check, it does not make pnpm install faster.
