# T1038 — component states are measured where they can be driven (issue #21 R6)

**Task:** issue #21 R6: pressed/loading/disabled/success/error had no instrument, which is why issue #15's
fifth box read "partly".
**Approval:** D32 issue triage inside D28; owner asked for the remaining proposals.
**Branch / base:** `chore/continuation-reconciliation` at `5a5645d`.

## Verdict

**Pass on two of the five states, with the other three named.** `pressed` and `disabled` are real DOM
states and are driven; `loading`, `success` and `error` are application states, and setting a guessed
`.is-loading` class would measure our guess rather than the product, so every report says they were not
driven. That sentence is in the check detail, the finding text and `docs/LIMITATIONS.md`.

## Why partial is the honest shape

| State | Drivable generically? | What happens |
| --- | --- | --- |
| pressed | yes — a pointer press | driven; changed computed properties counted |
| disabled | yes — the control's own attribute | driven; changed properties counted |
| loading | no — application state | named as not driven |
| success | no — application state | named as not driven |
| error | no — application state | named as not driven |

A probe that sets `class="is-loading"` measures whether we guessed the class name, not whether the
product shows a loading state. The same rule that stopped the audit inventing a transition scenario
(T1036) applies here.

## What is measured

Ten computed properties that make state visible (`background-color`, `background-image`,
`border-top-color`, `box-shadow`, `color`, `filter`, `opacity`, `outline-color`, `outline-style`,
`transform`), snapshotted at idle, during a real `mouse.down()`, and while disabled.

| Fixture | check | Detail |
| --- | --- | --- |
| `fixtures/bestpractice/states` (has `:active` feedback) | **pass** | `button.primary: pressed changed 2/10 style properties, disabled changed 3/10` |
| `fixtures/bestpractice/states-flat` (no `:active`) | **fail** | same line with `pressed changed 0/10`, plus a P2 finding |
| a page with no interactive control | **not-run** | `no interactive control (button, link, submit input) on this route: nothing to drive` |

The finding a failing control produces:

```
P2 No press feedback on button.primary
   expected 1 changed style properties on press · observed 0 changed style properties on press
   remediation: add a visible pressed state, visible under prefers-reduced-motion
```

## Wiring

| Path | Change |
| --- | --- |
| `packages/eval-core/src/harness/states.ts` | `probeStates` / `probeStatesWith`: up to three controls per route, pointer press and disabled state, `notDriven` always populated |
| `audit/contract.ts` | new check `component-states` (audit-only evidence, `gate: null`, deep mode, not required) and a new `AUDIT_WILL_NOT` line |
| `audit/pipeline.ts` | `collectStates`, one guarded browser for all routes |
| `audit/compose.ts` | check status from the measured controls + one P2 finding per control that acknowledges neither state |
| `bestpractice/from-audit.ts` | `component-states → visual`, so a scoped proposal can carry it |
| `docs/LIMITATIONS.md` | the two measured states, the three named, and the three-control cap |
| `fixtures/bestpractice/states`, `states-flat` | an honest control and a flat one, differing in one thing |

## Proof

`packages/eval-core/tests/component-states.test.ts` — 4 tests, green:

1. the honest fixture: press delta > 0, disabled delta > 0, `notDriven` exactly `['loading','success','error']`;
2. the flat fixture: press delta 0, and a **real deep audit** of it fails the check with the P2 finding
   carrying `expected 1 / observed 0` and the descriptor as its location;
3. the honest fixture's audit passes with **no** component-state finding;
4. a page with no control is `not-run` with the reason (not a pass).

## Stated limits

- Three controls per route, in document order: a page with more interactive elements is partly measured,
  and the check detail names the descriptors it drove.
- Loading/success/error stay unmeasured by design; a page that shows them is not "verified" by this.
- The disabled probe sets the attribute on the loaded page and restores it, so nothing is written to the
  target and the audit stays read-only.
- The measurement is presence of *any* style change, not quality of the change: a control that shifts
  1 px passes, and judging whether a pressed state is *good* remains a human judgment.
