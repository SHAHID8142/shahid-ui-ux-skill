# T1030 — axe findings can belong to a selection (issue #21 R2, #15 residue)

**Task:** issue #21 R2 / #15: every axe finding carried a **rule id** as its location, so a scoped
proposal could not say "this violation is inside the element you selected" without guessing
containment from strings — which the attribution rule refuses to do.
**Approval:** D32 issue triage inside D28; owner said `go ahead` on the proposed T1030.
**Branch / base:** `chore/continuation-reconciliation` at `3a7415b`.

## Verdict

**Pass.** A `selector` scope in `deep` mode now gets an axe scan confined to that element (axe
`include`), and the resulting findings name the element as their location, so they reach the proposal.
The page-wide scan is untouched, so the G4 verdict still describes the whole page.

## Measured, on `fixtures/bestpractice/scoped-axe/index.html`

The fixture has exactly two deliberate defects: an unlabeled input **inside** `form#signup` and an
image without `alt` **outside** it.

| State | Page-wide axe findings | Scoped (`form#signup`) findings |
| --- | --- | --- |
| before T1030 | `image-alt`, `label` — both located at the rule id | none possible (attributed elsewhere) |
| after T1030 | `image-alt`, `label` (unchanged) | `label (critical) within form#signup @ form#signup`, `observed: 1 node`, `expected: 0` |

End to end through the real command:

```
sus-eval bestpractice --path fixtures/bestpractice/scoped-axe/index.html --scope '#signup' --mode deep
→ 4 item(s), 4 measured, 1 blocking
  P0 | fact | a11y | label (critical) within form#signup | form#signup
```

The off-scope `image-alt` violation is **not** in the proposal (`0 findings outside scope` on that
rule), which is the point: the scoped scan constrains what can be attributed.

## Second defect found and fixed while wiring it

`targetIsDirectory` was computed as `!target.includes('.') || existsSync(target)`, which is `true` for
a path like `fixtures/site/index.html` — a **file**. Every single-file `--path` therefore resolved no
selector (`no browser is available to resolve a selector`) and the scoped path was unreachable. It now
asks the filesystem (`statSync().isDirectory()`), and a single `.html` target is loaded via `file://`.

## Proof

`packages/eval-core/tests/bestpractice.scoped-axe.test.ts` — 5 tests, green:

1. no scope requested → no `within …` findings, and the page-wide findings still include both defects;
2. in-scope violation → one item, `location === 'form#signup'`, `expected 0 / observed 1`;
3. out-of-scope violation → never attributed to the scope, while its page-wide finding stays;
4. a selector axe cannot include → recorded as a scoped-scan failure, audit still completes;
5. through `runBestPractice` on a **single-file** target → scope resolved, item present, exit 1 (P0).

## Stated limits

- Only `selector` scopes, only `deep` mode; `component-path` still proposes nothing and `quick` has no
  browser phase.
- axe `include` covers the element and its subtree in the main document; shadow DOM and cross-origin
  frames are outside what this claims.
- Severity is the page-wide policy (serious/critical → P0) rather than a new scoped scale, so the two
  groups cannot disagree about what "serious" means.
