# T1051 — recovery honors apply-path containment, and 'missing' can never masquerade as a hash (audit finding T1003-6)

Date: 2026-11-18 · Agent: zcode-audit · Branch chore/continuation-reconciliation

## What changed

- **`packages/studio-bridge/src/paths.ts` (new)**: `insideRoot` extracted from `apply.ts` so the
  durable `Transaction` machinery can hold the same containment line without a circular import
  (apply imports transaction; transaction cannot import apply). `apply.ts` imports it and
  re-exports it, so existing importers (tests, index) are unaffected; the guard body is the
  committed cfd3049 version byte-for-byte (resolve-based, realpath parent, unresolved leaf).
- **`packages/studio-bridge/src/transaction.ts`**:
  - `prepare()` refuses an escaping target **before** reading any preimage (the preimage step
    would otherwise read — and the transaction later write — outside the root).
  - `apply()` refuses any manifest path that resolves outside the root, before writing anything.
  - `recover()` classification: an escaping path is a **conflict** (recovery stops and reports,
    never guesses); a stored digest that is not a real 64-hex SHA-256 (`missing`, `absent`,
    truncated, garbage) is a **conflict** — unverifiable manifests are never executed. The old
    classifier compared the literal sentinel `'missing'` against stored values, so a planted
    prepared manifest declaring `preimageSha256: 'missing'` matched a genuinely absent file and
    its postimage was written (or its deletion executed) anywhere the manifest pointed.
  - `TxFile.preimageMissing?: boolean` makes "the target did not exist" an explicit flag instead
    of a sentinel spelling; `verify()` also refuses escaping paths.
  - Roll-back of a create (preimageMissing) removes the file — the preimage was "absent"; before
    this the else-branch would have tried to read a nonexistent `preimage-N.bin`.

## Evidence

- `pnpm -w exec vitest run packages/studio-bridge/tests/transaction.test.ts packages/studio-bridge/tests/apply.test.ts`

  hand-edited escaping manifest + `apply()` → throws before any write; legitimate
  `preimageMissing` create inside the root rolls forward **and rolls back** (file removed);
  `prepare()` refuses an escaping target before any preimage read.
