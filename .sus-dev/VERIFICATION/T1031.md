# T1031 — `--scope page` proposes the page's own findings (issue #21 R1)

**Task:** issue #21 R1: `bestpractice --scope body` exited 0 "nothing to propose" even when the audit
failed a gate on that page for a **page-level** defect (missing meta description), because attribution
matched element descriptors and those findings are reported at their own route (`/`).
**Approval:** D32 issue triage inside D28; follows the owner's `go ahead` on the R-series.
**Branch / base:** `chore/continuation-reconciliation` at `34d93df`.

## Verdict

**Pass.** `--scope page` (also `document`, `whole page`) selects the document itself, resolves without
a browser, and proposes what the audit measured on that page — including findings that belong to no
element.

## The contradiction that made this worth doing

```
$ sus-eval bestpractice --path fixtures/…/index.html --scope page --mode deep   # before
scope not-found: nothing matches page; the selection may be stale — reselect or pass a component path
$ …while the same audit reported:  seo-structure G9 fail — missing meta description
```

A page with a failing gate produced a proposal with nothing in it. That is the "silently producing
nothing" failure mode the review named.

## After

```
$ sus-eval bestpractice --path fixtures/bestpractice/scoped-axe/index.html --scope page --mode deep
→ 7 item(s), 7 measured, 2 blocking            (exit 1)

| P0 | fact | a11y | label (critical)                            | `label`         |
| P0 | fact | a11y | image-alt (critical)                        | `image-alt`     |
| P2 | fact | a11y | Tap target below 44x44 css px on input#email | `input#email`   |
| P2 | fact | copy | img-alt on /                               | `/`             |
| P2 | fact | copy | meta-description on /                      | `/`             |
```

## Decisions and why

| Decision | Reason |
| --- | --- |
| A page scope attributes **by dimension**, not by selector | The page is the unit the audit measured; no element descriptor can be "outside" the document. This is a statement about the unit, not a containment guess. |
| No browser is opened to resolve it | The page is known; resolving `page` as a CSS selector produced "nothing matches page", which is how the old behaviour failed. |
| `body` stays an element | It is a real selector the browser resolves. Only the explicit tokens mean the document. |
| No confined axe scan for a page scope | The page-wide scan already measured exactly that unit; both would report the same violation twice under two labels. |
| `page` is a `ComponentKind` with all six dimensions and no "not applicable" | Every dimension was measured on exactly this unit, so declaring one out of scope would be an invented limit. |

## Second defect surfaced and fixed

With page-level findings finally reachable, the proposal contract refused the run:

```
error: proposal refused: fact-without-observation — f04a0c588b477d4b (copy: img-alt on /) is typed
       as a fact without an observation and evidence
```

The SEO checks judged correctly (`1 of 1 images missing alt`) but emitted no numbers, so a "measured"
finding could not carry an observation. `packages/scanners/src/seo.ts` now reports `observed`,
`expected` and `unit` for all seven checks, and `compose.ts` forwards them. The contract did its job:
the fix is at the measurement, not in a downgrade to "judgment".

## Proof

`packages/eval-core/tests/bestpractice.page-scope.test.ts` — 4 tests, green:

1. tokens recognised (`page`, ` Page `, `document`) and not confused with elements (`#signup`, `body`)
   or with `component-path`;
2. resolution needs no browser, runs all six dimensions, declares none not-applicable;
3. on a real deep audit: page-level findings (`meta-description on /`) are proposed, element findings
   are too, `unattributed` is 0, `dimensions` is all six;
4. every SEO check carries numeric `observed`/`expected`/`unit`.

## Stated limits

- A page scope shows axe findings under the audit's own location (a rule id), so it says *what* axe
  objected to rather than pointing at an element. Element scopes keep the confined scan (T1030).
- Multi-route audits: the proposal covers every measured route; the page scope is the document of each.
- `--focus` still narrows the dimensions, and an excluded dimension's findings are counted, not hidden.
