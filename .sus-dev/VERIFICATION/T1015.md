# T1015 — Stale capability and status text reconciled across the public surface

**Status:** done · **Milestone:** M10 · **Date:** 2026-11-16 · **Owner:** lead (root agent)

## Why

The tree had moved and the prose had not. `skill/SKILL.md` still called itself a "v0.1 skeleton"
and deferred a licensing question it cannot decide; the adapter capability matrix listed shipped
capabilities as unbuilt; `docs/LIMITATIONS.md` and the build handoff still described two dogfood
findings as open months after they were fixed and closed under T1007/T1008; `README.md` still said
implementation was not authorised and that no host held fresh smoke evidence; and two status pages
quoted progress counts (`103/105`, `98 of 100`) that `TASKS.json` had left behind.

A document that describes an earlier build is not a harmless lag. It is the same class of failure
as a gate that reports `pass` without running: a reader uses it to decide what is safe, and it
tells them the wrong thing. The repository already fails the build on a stale *progress figure*
(`scripts/lib/roadmap.mjs` `COUNT_CLAIM_FILES`) and on an unsupported *claim*
(`scripts/lib/claims.mjs`) — this task closes the remaining prose that neither checker could see
because it names no number and makes no comparative claim, only a stale fact.

## Guards

- **The generated record still wins.** `docs/SUPPORT_MATRIX.md` and `docs/compatibility.json` were
  rewritten by `pnpm support:write`, never by hand; `docs/LIMITATIONS.md` §5 now says so out loud,
  because a hand-copied summary of a generated table is exactly the thing that drifts.
- **"Built" is not "does the model's job".** Every `built: true` capability row keeps a
  `requiresModel` sentence naming what a CLI cannot do — deriving a thesis, applying a playbook to
  a specific screen. Without that split, flipping `built` would be a claim of autonomy.
- **The smoke contract is not weakened.** The `honest degradation` literal that
  `scripts/coord/smoke-host.mjs` greps for was preserved verbatim while the rows around it changed.
- **No limitation was upgraded into a claim.** `docs/LIMITATIONS.md` gained no new capability
  statement; it gained a *narrower* one — five checks against 36 playbooks, no host at
  `supported`, no cold-runner timing. `node scripts/check-claims.mjs` is what enforces that.
- **Stale findings are corrected where they are described, not deleted.**
  `docs/DOGFOOD_FINDINGS.md` keeps the original 343 px and 4.46:1 numbers verbatim as the record of
  the first run; §4 of this handoff and §4 of LIMITATIONS now point at the fix and the re-measurement
  instead of contradicting each other.
- **Progress figures are not restated in prose.** The two pages that carried `103/105` and
  `98 of 100` now name no count at all, which is the only version of that sentence that cannot
  become false. `COUNT_CLAIM_FILES` still fails the build if any of the five status documents
  puts a `N of M done` back.

  artifact and still stays `experimental`: that tier additionally requires Live Studio to pass,
  and Live Studio has not been exercised on any host. This task changed the *wording* of that gap,
  not the gap.
- **`skill/` is still not published to any host registry.** Reconciling its text does not install
  it anywhere, and no host-triggering eval was run — the recorded 4/4 figure is a deterministic

  `docs/RESUME_ON_NEW_MACHINE.md` no longer quote a live count, but `.sus-dev/SESSION_LOG.md` and
  `ROADMAP.md` still record the *past* wrong figures on purpose — that is the history of the bug,
  not a current claim, and deleting it would hide that the class of failure was found twice.
