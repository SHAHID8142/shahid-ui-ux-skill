# T1012 — `/sus audit`: an honest invocation contract and a composed read-only pipeline

**Status:** done · **Milestone:** M10 · **Date:** 2026-11-16 · **Owner:** lead (root agent)

## Why

Issue #13 asks for an audit command. The cheap version of that request is a second engine: a new
page walker that re-derives accessibility, budget, reflow and SEO verdicts next to `evaluateG4`,
`evaluateG5`, `captureMatrix`, `runHardeningMatrix` and `@sus/scanners`. Two engines disagree
eventually, and when they do the audit says "clean" while a release gate says "fail" — with no way
to tell which one lied.

So the audit is a *composition*: the existing evaluators keep their verdicts, and the audit decides
only what to run, what to cite, and how to report a check it could not run. The other half of the
job is the contract. A command that silently audits one route, or one viewport, or a host the
operator never authorized, produces a report that reads complete and is not.

## What was added

`packages/eval-core/src/audit/`, five layers with a one-way dependency chain:

| Layer | File | Responsibility |
| --- | --- | --- |
| contract | `contract.ts` | pure data: target kinds, modes, viewport set, check descriptors, exit codes, `--help` text, `assertAuthorizedUrl`, `parseRoutes`, `renderContractMarkdown()` |
| report | `report.ts` | Zod schema for a finding and the report, `stableFindingId`, `sortFindings`, `exitCodeFor`, `renderAuditMarkdown()` |
| compose | `compose.ts` | pure: turn evaluator output into findings. Imports `evaluateG4`, `evaluateG5`, `evaluateG11`, `checkSeo`, `scanText` — and computes nothing numeric itself |
| pipeline | `pipeline.ts` | every side effect: resolve the target, serve a local build on a loopback port, drive `captureMatrix`/`runHardeningMatrix`/`scanA11y`/`runLighthouse`, hash artefacts, write under `--out` |
| cli | `cli.ts` | parse argv, call `runAudit`, print markdown or JSON, exit with the report's code |

Concretely:

- **Targets.** `--path <dir>` for a local build (served on `127.0.0.1:0`, GET/HEAD only) or
  `--url <url>` for a live origin. Loopback is allowed by default; any other host must be named
  with `--authorize <host>`, so a typo cannot silently audit a third party. Non-http schemes and
  embedded credentials are refused.
- **Depth.** `quick` is static only (served/built HTML through `checkSeo`, sources through
  `scanText`); `deep` adds `captureMatrix`, `runHardeningMatrix`, `scanA11y` and `runLighthouse`.
  Nothing in quick mode launches a browser — the test suite depends on that.
- **Viewports.** `mobile-320` 320×568, `mobile-390` 390×844, `tablet-768` 768×1024,
  `desktop-1440` 1440×900. 320 is non-negotiable (G7); the other three are the capture anchors.
  Neither runner covers the set alone, so the contract documents the union and the audit reports
  an uncovered cell as `not-run` instead of pretending the capture matrix spoke for it.
- **Routing.** `--route /,/pricing` selects routes; a local target defaults to every HTML route
  found in the build. A requested route that does not exist is an error, not an empty report.
- **Output.** `audit.json`, `audit.md`, `shots/`, `evidence/` — all under `--out`; `--fix-plan`
  writes a proposal whose every entry says `requiresApproval: true, applied: false`.
- **Exit codes.** 0 clean, 1 P0/P1 findings, 2 usage or target error, 3 a required check was
  `not-run`. Code 3 exists because "I did not measure it" must not read as "it is fine" in CI.

`docs/AUDIT_COMMAND.md` is generated from `renderContractMarkdown()`, so the document and the
`--help` output are the same data. A test fails if they drift.

## Guards

- **No second engine.** `compose.ts` imports the gate evaluators; it does not re-derive a
  threshold. `pnpm verify` runs the same evaluators through the gates, so a disagreement would
  surface as a gate failure rather than as a quietly different audit verdict.
- **Read-only by construction.** The local server answers GET/HEAD and 405s everything else;
  artefact paths are written under `--out` only; a test audits a fixture directory and asserts the
  target's bytes are unchanged.
- **`not-run` is not `pass`.** Quick mode fills every browser phase with an explicit reason string;
  a missing browser or an unreachable host degrades the phase to `not-run` with the reason, and
  `exitCodeFor` then returns 3.
- **Stable ids.** `stableFindingId` hashes check + route + viewport + title, so re-running the same
  audit yields the same id sequence and a finding keeps its identity across runs.
- **Doc/contract parity.** `docs/AUDIT_COMMAND.md` equals `renderContractMarkdown()` byte for byte
  (checked: `IN_SYNC= true`).

## Commands and observed results

| Command | Exit | Observed |
| --- | --- | --- |
| `npx vitest run packages/eval-core/tests/audit.test.ts` | 0 | `Tests 39 passed (39)` across 4 describe blocks (contract 7, report 6, composed 8, pipeline 7, plus the T1013 evidence suite 11) |
| `npx tsc -p packages/eval-core --noEmit` | 0 | no diagnostics |
| `pnpm --filter @sus/eval-core build` | 0 | `dist/audit/{contract,report,compose,pipeline,cli}.js` emitted |
| `node packages/eval-core/dist/cli.js audit --help` | 0 | prints the contract; 8 checks documented, 7 will-not-do entries |
| `node packages/eval-core/dist/cli.js audit --path /tmp/audit-art/src --mode deep --out /tmp/audit-r1` | 1 | 12 findings, exit 1 as designed for P0/P1; target hash unchanged afterwards (`TARGET_UNCHANGED=yes`) |
| `node packages/eval-core/dist/cli.js audit --url https://example.com --out /tmp/audit-x` | 2 | `error: host "example.com" is not authorized: pass --authorize example.com to accept it explicitly`; no report written |
| `node packages/eval-core/dist/cli.js audit --path /nope --out /tmp/x` | 2 | clean failure before any measurement |
| `node /tmp/docsync.mjs` (render vs on-disk doc) | 0 | `IN_SYNC= true`, `CHECKS= 8` |
| `node scripts/check-claims.mjs` | 0 | `[PASS] 6 claim-bearing file(s) carry no unsupported claims` |

Reproducibility: two consecutive deep runs over the same fixture produced the same 12 finding ids
in the same order (`ID_SEQUENCE_EQUAL= true`). Only `checks` differed, and only in the ephemeral
loopback port embedded in the Lighthouse detail string (`127.0.0.1:51553` vs `:51583`) — recorded
here rather than hidden, because it is cosmetic and does not affect a verdict.

## Not claimed

- The audit does not replace the release gates. It reports the gates' verdicts with the evidence a
  reviewer needs; the gates remain the authority.
- Browser zoom at 400 % (the second half of G7) is still not measurable here and is reported as
  `not-run`. The 320 px measurement is not allowed to stand in for it.
- A remote target is audited only when authorized, and only the routes the operator names. Coverage
  of a site's whole route surface is the operator's job, not an inference this command makes.
- `transition-oracle` is `not-run` unless the target authored cases; absence is never a pass.
