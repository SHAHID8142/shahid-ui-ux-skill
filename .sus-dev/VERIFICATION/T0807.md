## What landed

### `packages/studio-web/src/keyboard-drawing.ts` — the keyboard path (DA-34)

`KeyboardDrawingController` draws rectangle / arrow / pen from keys alone and
emits the **same `AddInstruction`** the pointer path emits, carrying
`keyboardPath` and `typedEquivalent` (both required by the landed annotation
schema per DA-34):

- Arrows move the cursor (Shift = coarse step), clamped to the viewport;
  Enter places a corner/vertex; Backspace removes the last vertex;
  **Space finishes** a pen stroke (≥3 points) — added because "Enter finishes
  at ≥3" made it impossible to grow a stroke past three points (found while
  testing, fixed in the design rather than the test); Escape aborts;
  Tab cancels because focus left the canvas.
- Degenerate geometry is refused (two identical rectangle corners), matching
  the schema's per-kind point rules instead of letting the store reject it
  later.
- Every transition emits a polite live-region `announcement` — a keyboard
  path a screen-reader user cannot follow is a keyboard-shaped dead end.
- `typedEquivalent()` produces the canonical `sus-annotate <kind> <points>
  "<label>"` textual form, so a user who prefers typing produces
  byte-identical annotations.

### `packages/studio-web/src/a11y.ts` — list, focus, verdicts

- `AnnotationListModel` — ordered SR-facing list: `position`, accessible
  `name`, **semantic** geometry ("10% across … points from … to …", never raw
  pixels alone), the annotation's keyboard path, a summary for the list's
  accessible name ("2 annotations: 1 rectangle, 1 pen"), polite add/remove
  announcements and an assertive refusal announcement. Roving focus wraps and
  refuses ids that are not in the list.
- `OverlayFocusManager` — trap while open (Tab/Shift+Tab cycle inside),
  Escape closes and **restores** the element that opened the overlay, direct
  focus to unknown targets refused, closed-state key handling refused, empty
  target list rejected at construction.
- `emitG7Reflow` / `emitG8TargetSize` / `emitG9Semantics` — verdicts in
  `docs/GATE_REGISTRY.md` terms (`pass | fail | not-run | not-applicable`):
  - missing measurements → **not-run**, never pass (registry discipline:
    unimplemented/missing evidence never satisfies a gate);
  - `overflow: hidden` used to conceal horizontal scroll → **fail** (F17
    anti-cheat);
  - a WCAG 1.4.10 exception (data table, map, …) or a WCAG 2.2 SC 2.5.8
    exception (spacing, inline, equivalent control, user-agent, essential) →
    **not-applicable WITH `notApplicableReason`** (kilo H4), never a silent
    pass and never a fail;
  - project conventions — exactly one h1, 45–75 CPL, the stricter 44 px
    project target minimum — are **advisory detail only**, never gate
    failures (F16, F20).
