# T1037 — a file scope refuses to guess attribution (issue #21 R8)

**Task:** issue #21 R8: `--scope-kind component-path` resolved and then exited **0** with "nothing to
propose", while the audit had measured 51 findings on the same page. R8 allowed two endings: build a
descriptor→file map, or state the limitation at resolve time and refuse rather than exit 0 with nothing.
**Approval:** D32 issue triage inside D28; the owner's `go ahead` on the R-series.
**Branch / base:** `chore/continuation-reconciliation` at `da2a7f7`.

## Verdict

**Pass on the second ending**, which is the honest one available: mapping `input#email` to a source file
is not something this repository can do without inventing a rule, and inventing it would attribute one
element's defect to whatever file the user picked.

## The wrong answer that was being given

```
$ sus bestpractice --path fixtures/bestpractice --scope-kind component-path --scope motion/index.html --mode deep
nothing to propose in this scope          (exit 0)
```

Exit 0 means "measured and clean". What had actually happened: 51 findings were measured and **none of
them could be attributed to a file**. The word "nothing" hid which nothing it was.

## The answer now

```
$ sus bestpractice --path fixtures/bestpractice --scope-kind component-path --scope motion/index.html --mode deep
# Best practice proposal — not attributable to a file
Scope: `component-path motion/index.html` (generic)
The audit measured responsive, a11y, visual and reports 51 finding(s), but none can be attributed to a
file: a finding names an element (a descriptor such as `input#email`) and this scope names a source file,
so matching them would be a guess. Nothing was proposed and nothing was changed.

## What would work
Select the element instead of the file, e.g. --scope '#email' or --scope 'form#signup',
or ask for the whole document with --scope page.                                (exit 3)
```

| Case | Exit | Why |
| --- | --- | --- |
| file scope, findings that name elements | **3** | nothing in scope was measured — the audit's exit-code meaning for exactly this |
| file scope, genuinely nothing to change | **0** | measured and clean; the message stays "nothing to propose in this scope" |
| selector or page scope | unchanged | those can attribute, so nothing about them moved |

## Proof

`packages/eval-core/tests/bestpractice.file-scope.test.ts` — 2 tests, green:

1. a real deep run with `--scope-kind component-path`: outcome `resolved`, no proposal, **exit 3**, the
   markdown says the findings exist and cannot be attributed, names both remedies, and does **not**
   contain "found nothing to change";
2. a clean single page in quick mode: **exit 0** and the old message — so exit 3 is not a blanket change.

## Stated limits

- The descriptor→file mapping is still not built. This task makes the gap visible and typed, not closed.
- `--scope-kind editor-selection` follows the same rule (it is also a file path).
- The refusal is about attribution, not about reading the file: the file is still read to classify the
  component, and its dimensions still decide what was measured.
