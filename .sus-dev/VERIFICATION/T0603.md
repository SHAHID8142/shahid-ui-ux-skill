## The independence the acceptance asks for

The oracles consume **recorded observation traces**, never the state machine that
generated the transitions. An oracle built from the same generator could only ever
agree with itself: it would verify that the declarations match the declarations.
Everything here is decided from what a user could observe — state, readable text,
whether a change was visual-only, how long it lasted, whether the element was
still mounted, and the sequence number of whatever async result it reflected.

## The failure modes, each with the reason it matters

| Oracle | Failure it catches |
| --- | --- |
| `flash-as-only-feedback` | a state under 60 ms that was visual-only with no text change — a tint nobody can read and no assistive technology announces |
| `state-diverged` | after the last input, the UI settled elsewhere or oscillated (the toast-timer bug) |
| `stale-async-applied` | an older sequence applied after a newer one — the search box showing results for a query you already replaced |
| `unmount-left-interactive` | a control still interactive after unmount, i.e. a handler alive on a dead subtree |
| `reduced-motion-information-lost` / `-added` | the reduced trace carries different information than the default one (kilo M2: parity is information, not a CSS branch) |
| `hover-only-modality` | a keyboard or touch trace relies on a state only hover can reach |

A sub-settle visual state **with** a text change passes deliberately: the text is
the feedback, the tint is decoration. That distinction is tested in both
directions, because a checker that fails all fast states would be turned off within
a week.

## Determinism

No timers, no `setTimeout`, no wall clock: traces are authored on explicit
millisecond offsets (`SETTLE_MS` = 60 is the only threshold), so the suite cannot
flake — which is the recorded rollback for this task.

## Honest limitations

- **This emits the verdict; it does not capture the traces.** The browser-side
  recorder (real keyboard/touch/no-hover runs against a built fixture) is T0906
  work. Until then G6 can be *computed* correctly from evidence that does not yet
  exist in CI, which is exactly why the gate fails closed on an empty case list.
- `SETTLE_MS = 60` is a policy threshold, not a measured perceptual limit; it
  matches the fast-duration floor in the motion tokens (T0602).
- `Flash-as-only-feedback` cannot see a state announced via `aria-live` without
  visible text unless the recorder puts the announcement in `text`; the recorder
  contract is stated in the `Observation` type so T0906 supplies it correctly.
- Multiple failures are all reported (tested), because a component that flashes
  *and* diverges needs both fixes and a first-failure-only gate hides the second.
