## What actually runs

`pnpm dogfood` builds each fixture for real (`next build`, `astro build`), serves it
(`next start`, `astro preview --host 127.0.0.1`), and drives it in Chromium through
five checks, each bound to a rule the skill states:

| Check | Rule it makes checkable |
| --- | --- |
| `a11y-wcag-aa` | G4 — no serious/critical axe violation over the whole page |
| `reflow-390` | `search-filters.filters-continuity-across-layout` — no horizontal document scroll at 390 px |
| `focus-visible` | `tabs.tabs-roving-focus` — the first Tab stop paints a ring |
| `reduced-motion-quiet` | `accordion.accordion-reveal-height` — under `reduce`, no element keeps a >0 duration |
| `labelled-controls` | `form-input-validation` — every input has an accessible name |

Runtime: ~23 s for all three sites after their builds.

## The two findings (documented in `docs/DOGFOOD_FINDINGS.md`)

- **F1** `admin` overflows horizontally by **343 px at 390 px**, breaking the very
  reflow rule the second-wave playbooks state.
- **F2** `admin` footer + env note measure **4.46:1** contrast (`#6a7284` on
  `#f5f6f9`, 13 px) — 0.04 under AA, invisible to review, findable only by measuring.

Both are left **unfixed on purpose**: `evals/baselines/admin/page.html` is the
evaluation ruler, and changing the fixture in place silently rewrites every baseline
number. The fix belongs with a deliberate baseline refresh (T1001), which is exactly
the issue-#10 discipline applied to evidence.
