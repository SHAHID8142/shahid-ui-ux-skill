# T1058 — runBestPractice authorizes liveUrl before any browser contact (audit finding T1003-13)

Date: 2026-11-18 · Agent: zcode-audit · Branch chore/continuation-reconciliation

## What changed

`packages/eval-core/src/bestpractice/command.ts`:

- **Pre-authorization at the top of `runBestPractice`**: a non-null `liveUrl` is checked with the
  same rule the audit applies to its own target (`assertAuthorizedUrl`) before the scope browser
  or anything else exists. The library contract is a rejection naming the host and the remedy —
  the CLI already mapped refusals to exit 2 on every flag combination (audit-verified), so this
  closes the library API's contact-before-refusal window without changing any CLI behaviour.
- **`openScopePage` for a live URL now answers to the same boundary as every audit phase**:
  its Chromium launches behind `startAuthorizedProxy` (with
  `--proxy-bypass-list=<-loopback>`), document navigations are guarded, and the page the selector
  resolves on is asserted to be the authorised one. A `file://` scope page contacts no host by
  construction and keeps the plain launch.

## Evidence

- `pnpm -w exec vitest run packages/eval-core/tests/bestpractice.command.test.ts` → **15/15 pass**
  (includes the real deep fixture run and two new liveUrl tests).
- **New test 1 (the audit's dynamic repro, inverted):** a listener bound to the machine's own LAN

  --authorize …` and **the listener recorded zero requests**. The pre-fix behaviour (page load +

## Notes

- The refusal surfaces as a thrown `AuthorizationRefusedError`-class error from the library API
  (callers handle it; the CLI's `fail()` maps it to exit 2). Test 1 pins rejection, message, and
  zero contact.
- macOS note for future peers: 127.0.0.2 is not bindable (EADDRNOTAVAIL) — use the LAN IP or
  `.localhost` names for unauthorised-host tests.
