## Why this slice exists

Issue #10's remaining acceptance was about states, volume and long values: "Long IDs, long names,
translated labels, many records, empty/error/loading states, filters and sorting tested with

## Real defects this slice found and fixed

Found by the tests and the visual review, not by inspection:

1. **A `<th>` left as a table cell kept its intrinsic width inside an anonymous table wrapper**,
   which the 1px visually-hidden `<thead>` does not clip. At 200% text size that alone made the
   document 76px wider than the screen. Fixed by taking the header row out of the table layout
   (`display: block`, 1px box) below the reflow threshold.
2. **Two `minmax(11rem, …)` / `minmax(13rem, …)` grids** were 352px and 416px wide at 200% text
   size — wider than the 320px viewport. Fixed with `min(11rem, 100%)` / `min(13rem, 100%)`.
3. **The card label column at a flat `6.5rem`** left no room for the action button at 200% text.
   Fixed with `min(6.5rem, 45%)`.
4. **Five "Open" buttons with the same accessible name** — five indistinguishable items in a
   screen reader's button list. Each now names its record.
5. **The count was printed twice** on one screen (live region and pagination). Pagination now shows
   only the page position.
6. **Status pills carried no meaning**: Paid/Due/Overdue/Draft were all the same pale grey. Each
   now has its own AA-rated pair (overdue 6.59, due 6.63, paid 5.68, draft 8.38:1), and the record
   identity and amount are weighted above the action, which is now a quiet bordered button.

## Follow-up after the first CI run (run 43728500241, failure)

Two tests failed on the GitHub runner and passed locally. Both were real, and both were fixed at
the cause rather than by loosening the assertion:

1. **"announces the new count"** — the test waited for a sentence the *previous* load had already
   produced ("…page 1 of 3"), so on a slower runner it asserted while the status line still said
   "Loading invoices…". It now waits for the applied result itself (first row amount `$2,140.00`
   with no "Loading" in the status line). `Learned:` wait for the state you are asserting on, never
   for text that an earlier state can also satisfy.
2. **200% text size** — the runner's fonts are wider, and the overflow was **8px, from one
   heading**: "Workspace" at 48px measured 296px against a 256px box and could not wrap, so the
   document was 8px wider than a 320px viewport. Fixed with `overflow-wrap: break-word` on `body`
   (`anywhere` would have shrunk min-content and changed table column sizing). Reproduced locally
   by forcing a wide font stack (`Verdana, DejaVu Sans`), and the test now applies that stack
   itself so a Mac and the Linux runner measure the same way: 0 overflow at 200%, 210% and 220%.

Re-verify after the fix: `pnpm verify` exit 0 — 68 files passed + 3 skipped, 716 tests passed
+ 5 skipped.
