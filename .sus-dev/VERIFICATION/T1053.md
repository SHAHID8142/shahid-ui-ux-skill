# T1053/T1054/T1055 — three honesty-engine residuals (audit findings T1003-8, T1003-9, T1003-10)

Date: 2026-11-18 · Agent: zcode-audit · Branch chore/continuation-reconciliation

## What changed

- **T1053 (T1003-8)** `packages/eval-core/src/bestpractice/from-audit.ts`: `untestedFromReport`
  now also derives untested dimensions from **mode coverage**. Quick mode omits the browser checks
  from `report.checks` entirely, so an empty not-run list used to make the proposal print
  "Every dimension in scope was measured." while a11y, responsive, motion and performance were
  never measured. A check the requested mode does not carry now yields an untested-dimension row
  ("check `X` is not part of quick mode: the dimensions it measures were not measured, not
  passed"). A report without a mode reads as deep (the pipeline's default), which adds nothing —
  the pre-existing behaviour of reports that predate the field is preserved.
- **T1054 (T1003-9)** `packages/eval-core/src/audit/compose.ts` (`seoCheck`): the check status now
  derives from the same sub-check list `seoFindings` uses (`result.checks.some(status !== 'pass')`),
  so the row can never say pass while its findings carry P2s (title/meta were invisible to the old
  g3/g9-only derivation). Sub-check failures not already named in the g3/g9 detail are added to
  the detail, so a failing row names why.
- **T1055 (T1003-10)** `packages/eval-core/src/audit/compose.ts` (`keyboardFindings`): the two
  boolean-rule findings now carry measured observations — indicatorMissing:
  `expected 1 / observed 0 'visible focus indicator while focused'`; cycle:
  `expected 0 / observed N 're-focuses of the same element'`. A measured keyboard finding composes
  into a proposal as a fact instead of refusing the whole proposal with
  `fact-without-observation` (exit 2, no proposal). The contract's real target — an unmeasured
  fact — is still refused (those tests are untouched and pass).
