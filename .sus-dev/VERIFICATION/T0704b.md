## What this slice adds (and only this)

`packages/studio-web/src/annotations.ts` — DOM-free `AnnotationSessionStore`:

- ONE mutation entrypoint `apply(instruction)`: pointer / keyboard / automation
  inputs are the same typed instruction (structural DA-34 equivalence; the
  schema additionally REQUIRES `typedEquivalent` + `keyboardPath` per
  annotation, so non-drawing equivalence is data, not convention).
- Results, not exceptions: substrate `buildAnnotation` throws; the store
  converts failures to `{ ok: false, reasons }` (fail closed, no state change).
- Bounded undo/redo (100 snapshots, redo truncated on new mutation, empty
  history = explicit no-op failure); remove-by-id; undo restores removed
  entries in place. The id counter NEVER rewinds on undo — an undone id is
  never re-allocated to different geometry (aliasing hazard eliminated).
- Store policy cap: 500 annotations per session (substrate caps points at 512).
- Canonical serialization delegates to the substrate's schema-validated
  serializeSession/deserializeSession; parse deep-freezes its result.
- Constructor fails closed on non-integer/non-positive viewports.
- `packages/studio-web/package.json`: workspace deps on `@sus/schemas` +
  `@sus/studio-bridge`; `test` script via vitest (pattern parity with
  studio-bridge); vitest config (node env — the store is DOM-free by design).

## Peer review of the landed substrate (D33 duty)

Scope: `packages/schemas/src/annotations.ts`,
`packages/studio-bridge/src/annotations.ts` (landed+pushed); their suites
re-run green on this host inside the full verify. **Verdict: PASS.**
Verified good: strict records with per-kind superRefine point-count
invariants; normalized 0..1 semantic geometry (resize/zoom-surviving, never
raw pixels only); required typedEquivalent + keyboardPath (DA-34 enforced at
the data boundary); session-level duplicate-id rejection; undoLast safe on
empty; normalizePoint deterministic 4-dp rounding, clamp at capture;
schema-level hard rejection of out-of-range coords at the boundary (clamp is
capture UX only).

Findings filed on the bus (`finding --to zcode`), all forward constraints, no
code defects blocking this slice:

1. **LOW** — `Annotation.createdAt` is `z.string().min(4)`: any ≥4-char string
   validates (`"soon"`). `buildAnnotation` writes ISO strings, but the schema
   should pin the format (`z.string().datetime()` or a refine) so forged
   sessions cannot smuggle non-timestamps.
2. **LOW** — `deserializeSession` stringifies zod issues via
   `issues.map(String)` → `"invalid session JSON: [object Object]"`; issue
   detail is lost exactly where operators need it. Use the buildAnnotation
   pattern (`path.join('.') + ': ' + message`).
3. **LOW** — session serialization emits the bare record with no `{$id,
   version}` envelope: consumers cannot tell which schema version produced a
   file. ADR-005 keeps the version OUTSIDE the strict record — but something
   must still carry it. Suggest folding the envelope decision into T0709
   (lifecycle contract).
