## The decisions worth reading

- **Five outcomes, not a boolean.** `resolved` / `ambiguous` / `not-found` / `advisory` / `rejected`.
  Only `resolved` may proceed. `clarification` (what to ask) and `reason` (why refused) are separate
  fields so no caller has to parse prose to decide whether it may write.
- **Ambiguity returns candidates, never the first match.** `.card` matching three elements yields
  `ambiguous` with `div#c1, div#c2, div#c3` and `focus: null` — an unresolved scope offers no
  measurement plan, because measuring the wrong element is worse than measuring nothing.
- **A drawn region is `advisory` by construction.** A screenshot rectangle identifies pixels; issue
  #15 requires it be linked to source before it can drive a proposal, and this step refuses to
  pretend the mapping exists.
- **Descriptors carry no text.** Targets are `tag#id.class` (id preferred over classes, matching the
  metrics and tap-target selectors). Inner text would leak page content into reports; rationale
  strings and label checks are content-specific and belong to the dimensions that measure them.
- **Rejection happens before the browser.** Empty, `*`, `html *`, over 200 characters, or any control
  character is refused with a reason. A selector only ever reaches `document.querySelectorAll`
  inside the page — no shell, no `eval`, no interpolation anywhere.
- **The six dimensions always partition.** For every component class, `run ∪ notApplicable` covers
  exactly `responsive, a11y, motion, copy, performance, visual` and each exclusion carries a reason
  longer than a placeholder. A test asserts this for all seven classes, so adding a dimension later
  without deciding where it belongs fails loudly.
- **Performance and copy are refused where a number would be theatre.** No scripted interaction is
  driven for a single control, so `performance` is not-applicable rather than measured; cell wording
  is content, so `copy` needs a content kind before a rule can apply.
