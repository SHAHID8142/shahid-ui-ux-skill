## What was built

An Astro editor with the same contract as the JSX one — locate by anchor, splice
bytes, refuse rather than write:

- **Tokenizer** over the template only (frontmatter skipped): handles comments,
  doctype/processing instructions, quoted attribute values, `{}` expression
  nesting, and self-closing tags.
- **Matching close** by nesting depth for the same tag name, so nested same-name
  elements cannot be truncated.
- **Five operations**: `insert-child`, `insert-before`, `insert-after`,
  `replace-node`, `delete-node`. Indentation is inherited from the target; an
  inline element becomes multiline when a child is inserted rather than being
  spliced mid-sentence.
- **Refusals**: `target-not-found` (including map-instance anchors, which cannot
  be edited one-at-a-time without deciding the others), `ambiguous-target`,
  `self-closing-insert`, `empty-content`, `would-duplicate-anchor`,
  `post-edit-target-lost`, `post-edit-parse-failure` (template balance), and
  deleting `<html>`/`<body>`.
- **Boundaries**: frontmatter, `<style>` and `<script>` bodies are never edited;
  tests assert byte-identity outside the target element.

## Honest limitations

- Astro component syntax beyond markup (fragments, `set:html`, client directives)
  is treated as ordinary attributes; an edit inside a `set:html` string is not
  supported and would be refused only if it broke the anchor or the balance.
- The editor does not evaluate expressions, so an instance anchor must be edited
  by changing the loop/data (a different task) — the refusal is deliberate and
  tested.
- Template balance is a structural check, not a full Astro parse; it catches
  unbalanced tags (the realistic failure) but not semantic mistakes, which the
  `astro build` verification gate catches instead.
