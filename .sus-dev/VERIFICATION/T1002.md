## What the protocol actually enforces in code

**Sealing.** The three held-out briefs are identified by SHA-256 in
`seals.json`; `checkSeals` reports `drifted` (edited) and `missing` (deleted), and
either voids the run. The seal test reads the real files, so a future edit to the
held-out set fails `pnpm verify` — the "never inspected during tuning" promise stops
being a promise.

**Power (DA-43).** `n ≥ 20` is stated as a floor to validate, and the argument is
computed: a 0.5-point difference on the 1–5 scale with sd 0.8 needs **41 per arm**;
with sd 1.0 it needs **63**. The protocol therefore declares a **1.0-point** minimum
claimable effect, for which 20 per arm is sufficient, and says plainly that 20 is
underpowered for 0.5.

**Claim gate.** `comparativeClaimAllowed` requires all three arms `measured`, the
held-out set uninspected, and `reproducibleBy: 'pnpm benchmark'`. Today it returns
`allowed: false` with reasons `['sus-assisted: not-run', 'human: not-run']`.

## Honest limitations

- **No human run.** There are no participants, so there is no human result and no
  comparative claim. This is the acceptance requirement, not a shortcut.
- **The `sus-assisted` arm did not run.** Held-out briefs have not been used to
  generate assisted artefacts; doing so is the next honest step and needs a
  generation harness scoped to the sealed set.
- The deterministic arm tests the **baseline** artefacts, which is one axis; the
  primary axis (blind designer scoring) is exactly the part that is missing.
- The rubric referenced by the protocol is the existing one; rater-facing sheets and
  randomisation materials are not generated yet.
